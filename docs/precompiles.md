# 以太坊预编译地址

日期：2026-11-10

预编译是客户端里写死的函数，挂在固定地址上。合约用 `CALL` 把原始字节交给这个地址，客户端用本地代码计算结果再写回返回数据。账户里即使存了字节码，调用这个地址时也不执行那段字节码。

这里的地址和 gas 按 go-ethereum 的 `core/vm/contracts.go`、`params/protocol_params.go` 整理，对应到 Osaka。minichain 只实现了其中的 `0x01`。

## 为什么要有预编译

这些运算用 EVM 字节码也能写出来。预编译把其中又常用、又贵的几种做成了本地代码，每次调用只收一笔固定的、或按输入长度线性增长的 gas。

椭圆曲线点乘、配对、大整数模幂，在字节码里要展开成大量 `MULMOD` 和内存读写。`ecrecover` 用预编译是 3000 gas；同一套 secp256k1 恢复用字节码做，通常是几十万 gas，一笔交易里往往只够验一次。BN254 配对和 BLS12-381 的多标量乘更重，字节码版本会顶到区块 gas 上限，zk 证明和 BLS 签名就没法放进合约。

EVM 已经有 `KECCAK256` 操作码，因为每笔合约都要算存储槽和函数选择器。SHA-256、RIPEMD-160、secp256k1、BN254、BLS12-381、secp256r1 没有对应操作码。预编译是不增加操作码的扩展口：硬分叉时往地址表里加一项，所有合约立刻可以调用，不需要有人部署，状态里也不保存这段代码。

每条客户端对同一个输入必须给出同一个输出。预编译的边界、失败条件和 gas 都写在 EIP 里，并用测试向量对齐。新曲线在用量还没大到值得硬分叉时，仍然用普通合约实现。

## 调用时发生什么

调用不带函数选择器。`cast abi-encode` 拼出的只是参数字节；`cast calldata` 会在前面多 4 字节选择器，预编译会把这 4 字节当成输入的开头。

`CALL` 先把金额记到目标地址，再查预编译表。gas 够且预编译返回成功，金额留下。返回错误或 gas 不够，这次调用撤销，金额回到调用方。`ecrecover` 遇到不合法签名时返回空，并且算成功，金额不退。一笔普通转账只有 21000 gas，不够 `ecrecover` 的 3000，金额到不了 `0x01`。

预编译本身不做 `CALL`，也不做 `SELFDESTRUCT`。已经留在这些地址上的余额，没有由协议执行的转出路径。要转出，得有该地址的私钥来发一笔普通交易。`0x01` 到 `0x11` 以及 `0x100` 的私钥没有人有。

`DELEGATECALL` 不转移金额。`STATICCALL` 也不能附带金额。带金额的 `CALLCODE` 在以太坊里检查的是调用方自己的余额，金额不会记到预编译地址上。

## 地址一览

gas 里的「字」是 32 字节，长度向上取整。下表的曲线 gas 是 Istanbul 及之后的价格；Byzantium 上 BN254 更贵，见后面的分叉小节。

| 地址 | 名称 | 从哪次分叉开始 | 作用 | gas |
| --- | --- | --- | --- | --- |
| `0x01` | ECRECOVER | Homestead | 从 secp256k1 签名恢复地址 | 3000 |
| `0x02` | SHA256 | Homestead | SHA-256 | 60 + 每字 12 |
| `0x03` | RIPEMD160 | Homestead | RIPEMD-160，结果左填充到 32 字节 | 600 + 每字 120 |
| `0x04` | ID | Homestead | 把输入原样返回，当作便宜的内存复制 | 15 + 每字 3 |
| `0x05` | MODEXP | Byzantium | 计算 `base^exp mod mod` | 见下文 |
| `0x06` | BN254_ADD | Byzantium | BN254 曲线上两点相加 | 150 |
| `0x07` | BN254_MUL | Byzantium | BN254 标量乘 | 6000 |
| `0x08` | BN254_PAIRING | Byzantium | BN254 配对检查 | 45000 + 每对 34000 |
| `0x09` | BLAKE2F | Istanbul | BLAKE2b 压缩函数 | 等于输入里的轮数 |
| `0x0a` | KZG_POINT_EVALUATION | Cancun | 验证 blob 的 KZG 证明 | 50000 |
| `0x0b` | BLS12_G1ADD | Prague | BLS12-381 的 G1 点加 | 375 |
| `0x0c` | BLS12_G1MSM | Prague | BLS12-381 的 G1 多标量乘 | 按点数打折 |
| `0x0d` | BLS12_G2ADD | Prague | BLS12-381 的 G2 点加 | 600 |
| `0x0e` | BLS12_G2MSM | Prague | BLS12-381 的 G2 多标量乘 | 按点数打折 |
| `0x0f` | BLS12_PAIRING | Prague | BLS12-381 配对检查 | 37700 + 每对 32600 |
| `0x10` | BLS12_MAP_FP_TO_G1 | Prague | 把基域元素映射到 G1 | 5500 |
| `0x11` | BLS12_MAP_FP2_TO_G2 | Prague | 把二次扩域元素映射到 G2 | 23800 |
| `0x100` | P256VERIFY | Osaka | 验证 secp256r1 签名 | 6900 |

`0x00` 不是预编译。转到零地址的币同样没有已知私钥可以转出，那是另一个地址。

## 每个地址的输入和输出

### `0x01` ECRECOVER

输入 128 字节：哈希、`v`、`r`、`s`，各 32 字节。`v` 这一字只有最后一字节可以是 27 或 28，前面 31 字节必须是 0。`r`、`s` 要落在 1 到曲线阶减 1。

成功时返回 32 字节，地址在末尾 20 字节。签名不合法时返回空，调用仍然成功。这是合约验 `permit`、元交易和链下签名的入口，曲线与以太坊交易签名相同。

### `0x02` SHA256 与 `0x03` RIPEMD160

输入是任意长度的原文。SHA-256 返回 32 字节摘要。RIPEMD-160 的摘要是 20 字节，左填充成 32 字节。比特币地址和一部分跨链校验用这两只哈希；EVM 没有对应操作码。

### `0x04` ID

返回的字节与输入相同。它给大块内存复制一条按字计价的路径，复制本身不需要在合约里写 `MLOAD`/`MSTORE` 循环。

### `0x05` MODEXP

输入开头是三个 32 字节长度 `baseLen`、`expLen`、`modLen`，后面依次是底数、指数和模数。输出是模幂结果，长度等于模数。RSA 验签和一些零知识电路用它做大整数模幂。

gas 随长度和指数的有效位变化。Berlin（EIP-2565）把公式改便宜，最低 200。Osaka 同时启用 EIP-7823 和 EIP-7883：底数、指数、模数任一超过 1024 字节就失败，最低 gas 改为 500，乘法复杂度也重新定过价。

### `0x06` 到 `0x08` BN254

曲线是 BN254（也叫 alt_bn128）。点加输入两个 64 字节的点，标量乘输入一个点和一个 32 字节标量，输出都是 64 字节的点。配对输入是若干 192 字节的对，配对结果为 1 时返回 32 字节的 `1`，否则返回 32 字节的 `0`。输入点不在曲线上时调用失败。

Byzantium 引入这三项，用来在链上验证 zk-SNARK。当时点加 500、标量乘 40000、配对 100000 再加每对 80000。Istanbul（EIP-1108）降到上表里的价格。

### `0x09` BLAKE2F

输入固定 213 字节：前 4 字节是大端轮数，随后是状态、消息块、偏移和最后一块标志。gas 就等于这个轮数。它是 BLAKE2b 的压缩函数，用来在合约里增量计算 BLAKE2b。输入长度不对，或最后一块标志不是 0 或 1，调用失败。

### `0x0a` KZG 点估值

Cancun 的 blob 交易把数据放在共识层，执行层只看到版本化哈希。这个预编译核对：承诺的版本化哈希与承诺一致，并且 KZG 证明能打开到给定的点和取值。

输入 192 字节：版本化哈希 32、求值点 32、取值 32、承诺 48、证明 48。成功时返回固定的 64 字节，内容是域模数。长度不对、哈希对不上或证明失败，调用失败。

### `0x0b` 到 `0x11` BLS12-381

Prague 的 EIP-2537 把 BLS12-381 放进执行层。BLS 签名聚合、部分共识轻客户端证明和较新的零知识系统用这条曲线。点的编码比 BN254 宽：G1 点 128 字节，G2 点 256 字节，坐标放在每段末尾。

| 地址 | 输入 | 输出 |
| --- | --- | --- |
| `0x0b` | 两个 G1 点，共 256 字节 | 一个 G1 点，128 字节 |
| `0x0c` | `k` 组「G1 点 128 字节 + 标量 32 字节」 | 一个 G1 点，128 字节 |
| `0x0d` | 两个 G2 点，共 512 字节 | 一个 G2 点，256 字节 |
| `0x0e` | `k` 组「G2 点 256 字节 + 标量 32 字节」 | 一个 G2 点，256 字节 |
| `0x0f` | `k` 组「G1 点 128 字节 + G2 点 256 字节」 | 32 字节，配对为 1 时末字节是 `0x01` |
| `0x10` | 64 字节基域元素 | 一个 G1 点，128 字节 |
| `0x11` | 128 字节二次扩域元素 | 一个 G2 点，256 字节 |

多标量乘的 gas 是 `k × 单次标量乘 × 折扣 / 1000`。G1 单次按 12000 计，G2 按 22500 计，点数越多折扣越大。长度不是一组的整数倍、域元素超出范围或点不在正确子群，调用失败。点加不检查子群。

### `0x100` P256VERIFY

Osaka 加入，地址是 `0x100`，不是 `0x12`。它验证 secp256r1（P-256）签名，WebAuthn 和通行密钥用这条曲线。

输入 160 字节：消息哈希、`r`、`s`、公钥 `x`、公钥 `y`，各 32 字节。验签通过返回 32 字节的 `1`。长度不对或验签失败都返回空，并且算成功。gas 固定 6900。实现注释仍标着 EIP-7212，主网这条预编译的规格是 EIP-7951。

## 分叉上各有哪些

| 分叉 | 地址 |
| --- | --- |
| Homestead | `0x01`–`0x04` |
| Byzantium | 加上 `0x05`–`0x08` |
| Istanbul | 加上 `0x09`，并降低 BN254 的 gas |
| Berlin | 地址不变，`0x05` 改用 EIP-2565 的 gas |
| Cancun | 加上 `0x0a` |
| Prague | 加上 `0x0b`–`0x11` |
| Osaka | 加上 `0x100`；`0x05` 限制单项不超过 1024 字节，并改用 EIP-7883 的 gas |

## minichain 里有什么

minichain 的预编译表只有 `0x01`。`CALL`、`CALLCODE`、`DELEGATECALL`、`STATICCALL` 和交易入口打到这个地址都走 `chain/precompile.go`，不解释账户代码。输入布局与上面的 ECRECOVER 相同。签名不合法返回空，调用成功。gas 固定 3000，不够则这次调用失败，附带的转账撤销。
