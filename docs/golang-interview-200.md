# Go 常见面试题 200 题（含答案）

基准是 Go 1.26 的语言规范和标准库（核对过本机 `go1.26.1` 的 runtime 与标准库）。实现细节会变，语义不会随便变。某条行为从哪个版本开始、以及它是否受 `go.mod` 里 `go` 行控制，下面会单独写出。

`encoding/json/v2` 到 1.26 仍是 `GOEXPERIMENT=jsonv2` 才启用的实验 API。下面说 JSON 时，默认都指 `encoding/json` v1。

## 1. 语言与类型

### 1. Go 程序从哪开始执行？`init` 和 `main` 谁先？

**答：** 可执行程序必须是 `package main`，入口是 `func main()`。`main` 没有参数也没有返回值，命令行参数在 `os.Args`。

一个包里的初始化顺序是：先按依赖把导入的包初始化完，再按文件名的字典序、文件内的声明顺序初始化包级变量，最后按同样顺序执行所有 `init`。`init` 可以有多个，不能手动调用。全部 `init` 结束后才进入 `main`。程序从 `main` 返回后进程退出，还在跑的 goroutine 会被直接停掉，没有 [happens-before](./happens-before.md) 保证。

### 2. 标识符什么时候包外可见？

**答：** 看名字的首个字符是不是 Unicode 大写。大写导出，小写只在包内可见。可见性按包，不按目录、不按文件。同一个包可以拆在多个文件里，这些文件互相能访问未导出名字。

结构体字段、方法也遵守这条规则。外部包不能用[复合字面量](https://my.feishu.cn/wiki/Ba4gwtv7CiO95HkB1UycnCbonEd)给未导出字段赋值，也不能直接读写未导出字段。

### 3. `var` 和 `:=` 有什么差别？短声明什么时候算重新声明？

**答：** `var` 可以写在包级或函数内。`var x T` 不写初值时，`x` 是类型 `T` 的零值，不是所有类型都变成数字 `0`。数值是 `0`，`bool` 是 `false`，`string` 是 `""`，指针、切片、map、函数、接口、channel 是 `nil`，数组和结构体是每个元素、每个字段各自的零值。所以 `var wg sync.WaitGroup` 是计数为 `0` 的结构体，不是 `nil`。`:=` 只能写在函数内，至少要声明一个新变量。

同一代码块里可以写 `x, y := 1, 2`，即使 `x` 已经存在，只要 `y` 是新的，`x` 就是赋值。内层代码块里的 `:=` 会声明新变量，把外层同名变量挡住。`if`、`for`、`switch` 的短声明作用域是对应语句，不是外层函数。

### 4. 常见类型的零值是什么？零值能不能直接用？

**答：** 数值是 `0`，布尔是 `false`，字符串是 `""`，指针、切片、map、函数、接口、channel 都是 `nil`。数组和结构体的零值是每个字段的零值。

golang「零值」设计成「可用」：`nil` 切片可以 `len`、`range`、`append`；零值 `sync.Mutex`、`bytes.Buffer`、`strings.Builder` 可以直接用。`nil` map 可以读，不能写。`nil` channel 的发送和接收会永远阻塞。`nil` 函数、`nil` 接口调用会 panic。

### 5. 常量和 `iota` 怎么工作？

iota，读音 /aɪˈəʊtə/，是希腊字母表第 9 个字母

**答：** 常量在编译期求值。未显式给出类型的常量是**无类型常量**，精度可以高于任何具体类型，直到赋给一个装不下它的类型才报错。

`iota` **在每个** `const` **块从 0 开始，「每出现一条常量声明加 1」。同一行的多个标识符共用同一个** `iota`：

```go
package main

import "fmt"

const (
	A, B = iota, iota // 0, 0。同一行共用同一个 iota
	C    = iota       // 1。必须显式写表达式：省略会抄上一行的 iota, iota，一个名字对两个值，编译失败。这里写成 iota，后面省略表达式的行才跟着各自的行号走
	D                 // 2。重复 C 的表达式 iota，用的是本行序号 2
	_                 // 3。赋给空白标识符后丢掉，这一行的序号仍然占用
	E                 // 4。同样重复 iota，本行序号是 4
	F    = iota + 1   // 6。本行 iota 是 5，5+1=6
	G                 // 7。重复 F 的表达式 iota+1，本行 iota 是 6，6+1=7。不是把 F 的值 6 再加 1
)

func main() {
	// 输出: 0 0 1 2 4 6 7
	fmt.Println(A, B, C, D, E, F, G)
}
```

跳过某个值时用 `_`。`iota` 出现在表达式里就按当时的值计算，不会在运行时变化。

### 6. `int`、`byte`、`rune` 分别是什么？

**答：** `int` 和 `uint` 的宽度跟平台走，64 位平台上是 64 位。需要稳定宽度或做协议、文件格式时用 `int32`、`int64`、`uint32` 这类明确类型。

`byte` 是 `uint8` 的别名，表示原始字节。`rune` 是 `int32` 的别名，表示一个 Unicode 码点。字符串的 `len` 是字节数，不是 rune 数。

### 7. Go 的指针能做什么？

**答：** 可以取地址、解引用、把指针传给函数从而修改调用方的变量。没有指针运算，不能把 `*int` 加一个偏移去踩相邻内存。`unsafe.Pointer` 能做这类转换，但它绕过了类型系统，不保证后续版本的内存布局仍然允许你那么写。

任何类型的 `nil` 指针解引用都会 panic。指针本身是可比较的，比较的是地址。

### 8. `new` 和 `make` 的区别是什么？Go 1.26 的 `new` 变了什么？

**答：** `make` 只用于 slice、map、channel，它会把内部结构准备好（底层数组、哈希表、队列），返回的就是这个类型本身，不是指针。

Go 1.25 及以前，`new(T)` 只能接收类型，分配一个 `T` 的零值并返回 `*T`。Go 1.26 起 `new` 也可以接收表达式，用这个表达式的值做初值：

```go
age := new(yearsSince(born)) // *int，值是函数结果
```

`new` 不会把 map 或 channel 初始化成可用容器。`new(map[string]int)` 得到的是指向 `nil` map 的指针，写入仍会 panic。

### 9. Go 是值传递还是引用传递？

**答：** 只有值传递。参数和赋值都是复制那个值。

切片复制的是头：指针、长度、容量。map、channel 复制的是指向运行时对象的指针。接口复制的是类型信息和数据。函数里通过这些指针改到底层数据，调用方能看见；把形参重新赋成另一个切片、另一个 map，调用方的变量不会变。`append` 一旦扩容，新切片指向新数组，调用方持有的旧切片仍指向旧数组。

### 10. 空白标识符有哪些用途？

**答：** `_` 丢掉不需要的值：`_, err := f()`。导入包只为了执行它的 `init`：`import _ "image/png"`。在 `import` 里用点导入是另一回事，点导入会把名字倒进当前包，一般不这么写。

`_` 不是变量，没有地址，不能读取。

### 11. 多返回值和命名返回值怎么选？

**答：** 多返回值就是多个结果，习惯把 `error` 放在最后一个。调用方想忽略某个结果就用 `_`。

命名返回值会在函数开头按零值创建，裸 `return` 返回它们的当前值。它适合结果含义不直观、或者 `defer` 需要改返回值的函数。名字会进入文档，太随意的名字会把 API 写差。不需要这些能力时，普通返回值更直白。

### 12. 闭包捕获的是什么？

**答：** 捕获的是外层变量本身，不是捕获那一刻的副本。闭包执行时读到的是变量当时的值。

```go
x := 1
f := func() int { return x }
x = 2
_ = f() // 2
```

要冻结当前值，把值当成参数传进去，或者先赋给一个新的局部变量。Go 1.22 起，`for` 用 `:=` 声明的循环变量每次迭代都是新变量，这和闭包捕获是两件事，见第 102、104 题。

### 13. 可变参数是什么？`append` 为什么能一次追加一个切片？

**答：** `func f(a ...int)` 在函数内部就是 `a []int`。调用时 `f(1, 2)` 会先做成切片。已经有切片时用 `f(s...)` 展开，元素类型必须和可变参数一致。

`append` 的签名是 `append(slice []T, elems ...T)`。`append(s, t...)` 是把另一个切片的元素展开后追加。`append` 返回的可能是新切片，必须把返回值用回去。

### 14. 类型定义和类型别名有什么区别？

**答：** `type MyInt int` 是新类型。它和 `int` 不能混用，要显式转换；方法集是自己的，底层类型仍是 `int`。

`type YourInt = int` 是别名，和 `int` 是同一个类型。`byte`、`rune`、`any` 都是别名。Go 1.24 起类型别名也可以带自己的类型参数。

### 15. 类型转换和类型断言差在哪？

**答：** 转换 `T(v)` 是编译期就确定的，用来在允许的类型之间制造一个新值，例如数值之间、`[]byte` 和 `string`、底层类型相同的具名类型。

断言 `v.(T)` 只用在接口值上，问它的动态类型是不是 `T`。单值形式失败会 panic；`x, ok := v.(T)` 失败时 `ok` 为 false，`x` 是 `T` 的零值。`type switch` 是按动态类型分支。

### 16. 包级变量和 `init` 的相对顺序是什么？

**答：** 先变量，后 `init`。变量之间按依赖排序；没有依赖时，按文件名字典序，再按文件里的出现顺序。`init` 用同一套文件顺序。

导入包形成环是编译错误。一个包被多个包导入，也只初始化一次。

### 17. 空白导入有什么用？

**答：** `import _ "pkg"` 不使用包里的名字，但会执行该包的 `init`。标准库里数据库驱动、图像格式用这个注册自己。不要用空白导入做隐式的业务初始化，调用方看不出来程序为什么依赖它。

### 18. `internal` 目录限制的是谁？

**答：** `internal` 里的包只能被它的父目录树导入。`mod/internal/auth` 可以被 `mod/...` 导入，不能被模块外或其他兄弟树导入。这是编译器强制的，不是约定。

### 19. 为什么说 Go 没有继承？

**答：** 没有类型层次，也没有子类覆盖父类方法这套分发。复用靠组合：结构体嵌入字段，方法提升到外层；接口只描述需要的方法，由具体类型隐式满足。嵌入不是子类型，外层类型和内层类型不能互相替代，除非你真的做了转换或让外层去实现同一个接口。

### 20. 哪些类型可以用 `==`？哪些比较会 panic？

**答：** 布尔、数值、字符串、指针、channel、数组（元素可比较时）、结构体（全部字段可比较时）可以用 `==`。函数、切片、map 只能和 `nil` 比较。

接口值可以比较：两边动态类型相同且动态值相等则为真。动态类型不可比较时，这次比较在运行时 panic。所以不要把切片、map、函数放进接口后再用 `==`。

### 21. 整数溢出和除零是什么行为？

**答：** 无符号整数的 `+`、`-`、`*`、`<<` 按模 2^n 环绕。有符号整数的 `+`、`-`、`*`、`/`、`<<` 溢出时，结果由补码表示确定，不 panic。把超出范围的常量转成装不下的类型是编译错误。非常量整数之间的转换会截断到目标宽度，例如 `uint32(int8(uint16(0x10F0))) == 0xFFFFFFF0`。浮点或复数转换如果装不下，转换仍然成功，结果由实现决定。

整数除以常量 0 是编译错误，运行时除数为 0 会 panic。浮点除以常量 0 同样是编译错误。运行时的浮点除零，规范只要求不超出 IEEE 754，是否 panic 由实现决定。gc 不 panic：变量相除时 `1.0/0.0` 是 `+Inf`，`0.0/0.0` 是 NaN。

### 22. 浮点数能做 map 的键吗？

**答：** 浮点类型是可比较的，能做键。NaN 不等于任何值，包括它自己，用 NaN 当键可以放进去，但按 NaN 查找匹配不到。不要用 NaN 做键。

### 23. 普通字符串和原始字符串有什么差别？

**答：** `"..."` 解释转义，`\n` 是换行。反引号原始字符串不解释转义，也不能包含反引号，适合正则和多行文本。字符串内容是字节序列，源码里的非 ASCII 字符按 UTF-8 存。字符串字面量之间如果内容相同，编译器可以让它们共享存储，这是优化，不是语言保证的驻留。

### 24. `len`、`cap`、`copy`、`delete`、`clear`、`min`、`max` 各作用于什么？

**答：** `len` 用于数组、切片、字符串、map、channel（channel 的 `len` 是当前缓冲区里的元素数，并发时只能当瞬间观察，不能当同步）。`cap` 用于数组、切片、channel。

`copy(dst, src)` 复制 `min(len(dst), len(src))` 个元素，返回复制个数。`src` 可以是字符串、`dst` 是 `[]byte`。

`delete` 只用于 map。`clear` 从 Go 1.21 开始：对切片把元素设为零值并保留长度，对 map 删掉全部键。对 `nil` 切片或 `nil` map 调用 `clear` 是合法的。

`min` 和 `max` 从 Go 1.21 开始，参数必须都是同一类有序类型。任一参数是 NaN 时，结果是 NaN。

### 25. `any` 是什么？

**答：** `any` 是 `interface{}` 的别名，从 Go 1.18 起进入语言。它表示“任意具体类型的接口值”，不是泛型，也没有把动态类型记在编译期。要从里面取出具体类型，仍要断言。

## 2. 数组、切片、字符串

### 26. 数组和切片的差别是什么？

**答：** 数组长度是类型的一部分，`[3]int` 和 `[4]int` 是不同类型。数组赋值和传参会复制全部元素。

切片是一段数组的视图，本身是一个小的描述符。切片长度可以变，类型里不带长度。函数参数几乎总是用切片，除非长度是 API 的一部分，例如 `[32]byte` 这种固定摘要。

### 27. 切片在运行时由什么组成？

**答：** 三部分：指向底层数组的指针、长度、容量。用户看不到这个结构体，但 `len`、`cap`、下标和 `append` 都按它工作。两个切片头可以指向同一块数组的不同区间。

### 28. `a[i:j]` 和 `a[i:j:k]` 的长度、容量怎么算？

**答：** 三个下标要满足 `0 <= i <= j <= k <= cap(a)`。`a[i:j]` 的长度是 `j-i`，容量是 `cap(a)-i`。`a[i:j:k]` 的长度是 `j-i`，容量是 `k-i`。

三下标切片把容量截短，后面的 `append` 在写满这段容量后会分配新数组，不会再改到原数组里 `k` 之后的元素。

### 29. 什么时候两个切片共享底层数组？

**答：** 切片表达式、把切片传进函数、以及未扩容的 `append`，都还指向原数组。谁写入这个重叠区间，另一个切片都看得到。

```go
a := []int{1, 2, 3, 4}
b := a[1:3]   // len 2, cap 3，和 a 共享
b = append(b, 9)
// a 变成 [1 2 3 9]，因为 b 的 cap 够，没有换数组
```

### 30. `append` 怎样决定新容量？

**答：** Go 1.26 的 `nextslicecap` 规则是：

- 需要的新长度已经大于 `2*oldCap` 时，新容量至少是这个新长度。
- 否则，`oldCap < 256` 时容量翻倍。
- `oldCap >= 256` 时反复做 `newcap += (newcap + 3*256) >> 2`，从 2 倍平滑过渡到大约 1.25 倍，直到装下新长度。

之后还会按元素大小向上取整到分配器的 size class，所以实际 `cap` 可能比上面的数更大。这是运行时策略，不是语言规范保证的公式。旧资料里“小于 1024 翻倍，之后 1.25 倍”已经过时。

### 31. `append` 之后原切片还指向旧数组吗？

**答：** `append` 不修改传入的那个切片头。没扩容时，返回的切片和原切片共享数组，写入新元素可能覆盖共享区间。扩容时，返回的切片指向新数组，原切片的指针、长度、容量都不变。所以结果必须赋回去：`s = append(s, x)`。

### 32. `nil` 切片和空切片差在哪？JSON 里呢？

**答：** 两者长度、容量都可以是 0，`append` 和 `range` 都合法。差别是 `nil` 切片的指针是 `nil`，空切片指向一个长度为零的数组（经常是运行时的 `zerobase`）。

`encoding/json` 默认把 `nil` 切片编成 `null`，把空切片编成 `[]`。`nil` map 是 `null`，空 map 是 `{}`。实验中的 `encoding/json/v2` 会把 `nil` 切片和 `nil` map 编成空数组、空对象，那不是默认行为。

### 33. 函数里对切片 `append`，调用方看不看得到？

**答：** 改已有下标，调用方看得到，因为底层数组相同。`append` 的返回值如果没赋给调用方的变量，调用方的长度不会变。没扩容时，函数里 append 写进去的元素已经在共享数组里，但调用方的 `len` 仍是旧的，正常下标访问不到；随后调用方自己再 append，可能把这些元素盖掉。

### 34. `copy` 的规则是什么？

**答：** 复制个数是两个长度的较小值，目标放不下的部分被丢掉，源不够就只复制源的长度。返回值是实际复制的个数。目标和源重叠时行为定义良好，可以用来做滑动。`copy` 不会扩容。

### 35. 为什么小切片会把大数组留在内存里？怎么断开？

**答：** 切片只持有指向数组的指针。`big[1:2]` 仍引用整块数组，GC 不能回收数组的一部分。

`slices.Clip` 只是 `s[:len(s):len(s)]`，容量变了，底层数组还是那一块，解决不了这个问题。要断开，得复制到新数组：`slices.Clone(s[:n])`，或自己 `make` 再 `copy`。字符串子串同理，Go 1.20 的 `strings.Clone` 用来复制出独立底层字节。

### 36. `for range` 数组会复制数组吗？

**答：** `for i, v := range arr` 会先求值数组，也就是复制整份数组，循环里再改原数组不影响 `v`。`for i := range arr` 只要长度，不会为了元素把数组复制一遍。大数组应改成切片，或对数组指针做 range，避免这份复制。

### 37. `make([][]int, n)` 得到了什么？

**答：** 得到长度为 `n` 的切片，元素都是 `nil` 的 `[]int`。内层还没分配。要二维结构必须再给每一行 `make`。它不是 `n*m` 的连续矩阵。

### 38. 字符串为什么不能按下标赋值？

**答：** 字符串不可变。`s[i]` 读出的是第 `i` 个字节，类型是 `byte`，不能给它赋值。要修改就转成 `[]byte`，改完再转回字符串。这份转换在语言语义上是复制；编译器只有在能证明结果不会被改、从而不破坏不可变性时才可以省略复制。不要把“编译器有时能优化”说成“转换永不复制”。

### 39. `range` 字符串得到什么？

**答：** 每次得到的是字节下标和一个 `rune`。下标按字节走，不是 0,1,2 这样的码点序号。非法 UTF-8 会得到 `0xFFFD`，下标仍前进一个字节。

```go
s := "你a"
for i, r := range s {
    _, _ = i, r // 第一次 i==0，第二次 i==3
}
```

### 40. 字符串和字节切片怎么比较？

**答：** 字符串按字节比较，可以用 `==` 和 `<`。切片不能用 `==`，比较字节用 `bytes.Equal`，比较任意可比较元素用 `slices.Equal`。`bytes.Equal` 对两个 `nil` 或空切片返回 true。

### 41. 拼接字符串用 `+` 还是 `strings.Builder`？

**答：** 少量固定拼接，`+` 足够，编译器对相邻常量会直接合并。循环里用 `+` 会反复分配。`strings.Builder` 按字节追加，内部复用缓冲区，`String()` 返回目前内容。Builder 第一次写入之后不能按值复制，复制会 panic。

### 42. `bytes.Buffer` 和 `strings.Builder` 怎么选？

**答：** 结果是字符串并且只追加时用 Builder。`String()` 通过 `unsafe` 直接引用内部缓冲区，不再复制一份。后续 `Write` 只在现有长度之后追加，不会改写已经返回的那一段；本机 Go 1.26 上，`Grow` 出余量再 `WriteString("c")`，先前的 `"ab"` 仍是 `"ab"`。第一次写入之后不能按值复制，复制会 panic：`strings: illegal use of non-zero Builder copied by value`。

需要读走已写内容，或者结果就是字节时用 `bytes.Buffer`。`Buffer.String()` 会复制出一份新字符串。Buffer 使用后不要按值复制，复制不会立刻 panic，但内部切片和读下标会被拷走，随后的读写会错。

### 43. `range` 切片时，循环变量是副本吗？循环中 `append` 会不会被扫到？

**答：** range 表达式只求值一次，切片头被复制。每次迭代的值变量是元素的副本。元素是结构体时，改值变量不会写回切片；要改元素就用下标。元素是指针时，副本的指针仍指向同一对象。

循环次数是开始时的长度。循环里 `append` 出的新元素不会进入这次 range。如果 append 没有换数组，通过下标能看见对原区间的修改。

### 44. 切片为什么不能做 map 的键？

**答：** 键必须可比较。切片的相等没有定义，因为底层数组可能很大，而且切片头相等也不等于内容相等。要把一段字节当键，用字符串。字符串是不可变的，比较语义清楚。

### 45. 怎样按 rune 安全地切字符串？

**答：** `s[i:j]` 的下标是字节。切在码点中间会得到非法 UTF-8，这是允许的，字符串不要求永远是合法 UTF-8。要按字符切，用 `[]rune(s)`，或用 `utf8.DecodeRuneInString` 先算出完整码点的字节边界。转换 `[]rune` 会分配。

### 46. 对 `nil` 切片调用 `append`、`len`、`range` 呢？

**答：** 都合法。`len(nilSlice)` 和 `cap` 是 0，range 零次，`append` 会分配底层数组。对 `nil` 切片做下标读写会 panic。

### 47. 切片和数组分别能比较吗？

**答：** 数组在元素类型可比较时可以用 `==`，逐个元素比。切片除了和 `nil` 比较以外不能用 `==`。内容比较用 `slices.Equal`；需要排序意义时用 `slices.Compare` 或自己写。

### 48. 预分配切片有什么好处？

**答：** `make([]T, 0, n)` 或 `slices.Grow` 把容量一次准备好，后面的 `append` 在不超过这个容量时不再分配、也不再复制旧元素。长度仍是 0 时，`append` 从下标 0 开始填。`make([]T, n)` 则是已经有 `n` 个零值，适合按下标填充，不适合再 `append`，否则后面会多出 `n` 个零值。

### 49. 三个下标的切片解决什么问题？

**答：** 它限制共享数组上还能写多远。从大缓冲区里取一块逻辑上独立的数据时，写成 `buf[off:end:end]`，后续 append 会自己分配，不会把缓冲区里下一条消息的字节盖掉。

### 50. `string(bytes)` 之后改字节切片，字符串会变吗？

**答：** 不会。转换得到的字符串拥有自己的字节副本，之后改原切片看不到。反过来 `[]byte(s)` 得到的切片再修改，也不会改字符串。用 `unsafe` 让两边共享底层字节，一旦改了切片，就破坏了字符串不可变，属于未定义用法。

## 3. map

### 51. map 的语言语义有哪些是面试必须说清的？

**答：** 键必须可比较。读取不存在的键得到值类型的零值。用 `v, ok := m[k]` 区分“没有这个键”和“值刚好是零值”。遍历顺序故意不确定，也不能依赖某次运行里看起来稳定的顺序。`nil` map 可读、可 `len`、可 `delete`、可 `range`，写入会 panic。

### 52. Go 1.26 的 map 底层是什么？

**答：** Go 1.24 起内置 map 换成 Swiss Table，1.26 里这是唯一实现。一张表分成若干组，每组 8 个槽，配一个 8 字节的 control word：每个字节标记对应槽是空、已删除还是占用，占用时还存哈希的低 7 位。查找可以并行比较一组里的 8 个槽。

一个 map 可以有多张表，用哈希的高位选表，单张表容量上限是 1024 个元素。删除不会把槽简单挖空：如果后面的探测还依赖这个位置，就留下墓碑。这只说明实现，不改变上面的语义。Go 1.24 以前的“每桶 8 个键加溢出链”不要再说成当前实现。

### 53. `nil` map 上哪些操作合法？

**答：** 读、`len`、`range`、`delete`、`clear` 都合法，`delete` 和 `clear` 是空操作。`m[k] = v` 会 panic。函数里如果要写入，先判断并 `make`，或者由调用方保证 map 已创建。

### 54. 并发读写 map 会怎样？

**答：** 内置 map 不保证并发安全。并发写，或并发读写，会触发 `fatal error: concurrent map read and map write` 这一类运行时致命错误，进程退出，不是可以用 `recover` 接住的普通 panic。并发只读是允许的。

要并发访问就加锁，或者换 `sync.Map`。`-race` 能帮你找到没有立刻 fatal 的冲突，但不要靠“测试没崩”证明安全。

### 55. 为什么 map 遍历顺序是随机的？

**答：** 规范规定顺序未指定。运行时还会在遍历开始时加一个随机偏移，让程序无法依赖桶的物理顺序。需要稳定顺序就把键取出来排序，再按排序结果访问。

### 56. 什么能做 map 的键？

**答：** 键的类型必须可比较：布尔、数值、字符串、指针、channel、元素可比较的数组、字段全部可比较的结构体，以及接口。接口做键时，动态类型也必须可比较，否则那次读写会 panic。切片、map、函数不能做键。

### 57. 遍历时删除或新增键合法吗？

**答：** 删除当前已经遍历到的键，或者删除还没遍历到的键，都是定义好的：还没走到就被删掉的键不会再出现。遍历期间新增的键，可能被这次遍历看见，也可能不被看见。不要依赖新增键是否出现。

### 58. `delete` 之后 map 会把内存缩回去吗？

**答：** 不会。删除把槽标成空或者墓碑，墓碑多了以后，后续增长时可能整理，但 `delete` 本身不会把表缩成更小的容量。键值很大、又删得只剩几个时，旧的桶仍占着内存。要释放，就建一个新 map 把还需要的键拷过去，丢掉旧 map。`maps.Clone` 适合复制，不负责“压缩后替换”。

### 59. 为什么不能直接改 map 里结构体的字段？

**答：** `m[k]` 返回的是值的副本，不是可寻址的变量。结构体字段因此不能取地址，也不能在这个副本上改完写回。先把值取出来，改完再整份赋回去：

```go
v := m[k]
v.N++
m[k] = v
```

值是指针或切片时，副本里的指针仍指向同一对象，通过指针改对象可以，换掉 map 里的指针仍要整份赋值。

### 60. `sync.Map` 适合什么？

**答：** 适合键集合比较稳定、读多写少，或者多个 goroutine 各自碰不同的键。它的 `Load`、`Store`、`LoadOrStore`、`CompareAndDelete` 是并发安全的。

键一直在增删、读写都很多时，普通 `map` 加 `sync.Mutex` 往往更简单，也经常更快。`sync.Map` 的值要自己保证不被并发修改；它只保护 map 结构。`Range` 期间并发增删是允许的，但看到的是某一刻的混合结果。

### 61. 给 map 做并发封装要注意什么？

**答：** 把 map 和 `sync.Mutex` 放进同一个结构体，所有读写都走方法，不要把内部 map 暴露出去。`RLock` 只包住真正的读。不要在持锁时调用外部回调，回调再回来拿锁会死锁。需要“先查再插”的原子性时，整段逻辑放在同一把锁里，不要拆成两次加锁的调用。

### 62. map 的值是 `nil` 切片时追加元素要怎么写？

**答：** `append` 返回新切片，必须赋回 map：

```go
m[k] = append(m[k], x)
```

`nil` 切片可以直接 `append`。漏掉赋值的话，map 里仍是原来的 `nil` 或旧头。

## 4. 结构体、方法、接口

### 63. 结构体字段顺序为什么影响大小？

**答：** 每个字段按自身对齐要求放置，中间会插入填充。结构体的对齐是字段对齐的最大值，整体大小再补齐到这个对齐的倍数。把宽字段放在一起、窄字段放在一起，通常比宽窄交错更省填充。

可以用 `unsafe.Sizeof` 和 `unsafe.Offsetof` 看布局。布局是编译器的保证，不要在业务代码里手写偏移。

### 64. 空结构体有多大？地址能当唯一 ID 吗？

**答：** `struct{}` 的大小是 0。它做 channel 信号或 map 的值不会为每个元素再放一份数据。

规范不保证不同的零大小变量地址不同，gc 常常让它们指向 `runtime.zerobase`。所以 `&struct{}{}` 不能当唯一标识。

gc 还会在末尾的零大小字段后面补 1 字节，再按对齐取整，避免这个字段的地址和后一个对象重合。在 64 位上，`struct { a int64; b struct{} }` 的大小是 16，把空结构体放在 `int64` 前面则是 8。这是编译器的实现，不是规范写死的“加一个字节”。

### 65. 嵌入是什么？方法提升的规则是什么？

**答：** 结构体里写一个没有字段名的类型，就是嵌入。外层会提升内层的导出字段和方法，写起来像自己的一样，实际仍要经过内层值。提升不构成子类型。

外层自己定义了同名方法时，用外层的。嵌入的多个类型有同名方法、外层又没有自己的时，这个名字在外层是歧义，调用会编译失败，必须写出要哪一层：`o.A.M()`。

### 66. 值接收者和指针接收者怎么选？

**答：** 方法需要修改接收者、接收者很大、或包含 `sync.Mutex` 这类不能复制的字段时，用指针接收者。类型的方法集要一致：同一个类型上不要一半值、一半指针，否则使用者很难判断哪个接口被满足了。

小的不可变值，例如 `time.Time`，用值接收者是合理的。值接收者复制的是那一份值，方法里改副本不影响调用方。

### 67. 方法集的规则是什么？

**答：** 类型 `T` 的方法集只有接收者为 `T` 的方法。`*T` 的方法集包括接收者为 `T` 和 `*T` 的方法。

调用时，如果 `x` 可寻址，`x.M()` 在 `M` 是指针接收者时等价于 `(&x).M()`。map 的元素、接口里取出的具体值不可寻址，不能对它们调用指针接收者方法。把 `T` 放进接口时，只有值接收者方法算实现了接口；要把指针方法也算上，放进去的必须是 `*T`。

### 68. 接口值里面有什么？

**答：** 空接口（`eface`）存动态类型和数据。非空接口（`iface`）存 `itab`（接口类型、动态类型、方法表）和数据。数据若是指针就存指针；小的非指针值有时直接放在接口里，放不下或包含指针时会分配一份到堆上。所以把具体值赋给接口可能分配。

### 69. `nil` 接口和“里面放着 `nil` 指针”有什么区别？

**答：** 接口是 `nil` 当且仅当动态类型和动态值都是 `nil`。把一个类型为 `*T`、值为 `nil` 的指针赋给接口后，动态类型是 `*T`，接口本身不是 `nil`。

```go
var p *int
var i interface{} = p
_ = i == nil // false
```

这是错误处理里的常见坑：函数声明返回 `error`，里面 `var err *MyErr` 然后 `return err`，调用方的 `err != nil` 为真，尽管指针是 `nil`。要返回“没有错误”，就 `return nil`，不要返回带类型的空指针。

### 70. 接口怎么实现？

**答：** 隐式实现。类型的方法集包含接口的全部方法，就实现了这个接口，不需要 `implements`。方法签名必须完全一致，包括参数和结果的名字以外的类型。指针接收者的方法不会自动算进 `T` 的方法集。

### 71. 类型断言和 type switch 怎么写才安全？

**答：** 单返回值断言失败会 panic。不确定时用两返回值。type switch 按动态类型分支，`nil` 接口会走进 `case nil`：

```go
switch v := i.(type) {
case nil:
case int:
case string:
default:
    _ = v
}
```

`v` 在每个分支里的类型就是那个分支的类型，`default` 里仍是原接口类型。

### 72. 两个接口值比较时什么时候 panic？

**答：** 动态类型相同、且该类型可比较时，比较动态值。一边是 `nil` 接口时不会因为另一边的类型而 panic。两边动态类型相同但不可比较，例如里面都是切片，比较会 panic。

### 73. 空接口和泛型分别解决什么？

**答：** 空接口把类型检查推迟到运行时，容器里可以混放不同具体类型，取出时要断言。泛型在编译期就确定类型参数，`[]T` 里不会混进别的类型，也不需要断言。

能用具体类型或泛型表达的约束，不要先收成 `interface{}` 再在里面断言。空接口适合真正未知的类型，例如 `fmt.Println` 的参数。

### 74. 嵌入接口是什么意思？

**答：** 接口里嵌入另一个接口，新接口的方法集是两者的并。`io.ReadWriter` 嵌入 `Reader` 和 `Writer`。这是在描述方法集合，不是继承实现。具体类型只要有这些方法，就同时实现了大接口和小接口。

### 75. `io.Reader`、`io.Writer` 的约定是什么？

**答：** `Read` 可以在 `n > 0` 时同时返回非 `nil` 错误，调用方要先处理已经读到的字节。读到结尾返回 `io.EOF`。`0, nil` 不表示结束，调用方继续读是允许的，但实现应避免无进展的空读。

`Write` 必须在 `n < len(p)` 时返回非 `nil` 错误。不要忽略 `Write` 的错误，也不要假设一次 `Write` 一定写完全部。

### 76. 为什么 `String()` 里再调用 `fmt.Sprint` 可能死递归？

**答：** `fmt` 发现值实现了 `String() string` 就会调用它。在 `String()` 里如果把接收者再交给 `fmt`，会再次进来。对接收者的字段分别格式化，或用 `%v` 打一个没有 `String` 方法的别的类型。指针接收者和值接收者还会让 `T` 与 `*T` 一个实现了 `fmt.Stringer`、一个没有，打印结果会不一样。

### 77. 接口应该定义在哪一侧？

**答：** 定义在使用方。使用方写出自己需要的那几个方法，实现方不用依赖使用方的包。标准库的 `io.Writer` 就是这样：文件、网络、缓冲都去满足写入这一小块行为。

接口越小越好。把“一个类型的全部方法”复制成一个大接口，调用方就没法用测试里的假实现，也把无关方法耦进来了。

### 78. 外部包能不能用字面量构造含未导出字段的结构体？

**答：** 不能用 `pkg.T{unexported: 1}`，也看不到未导出字段。包自己可以提供构造函数。跨包的复合字面量只能写导出字段；没写的字段是零值。

### 79. 结构体什么时候不能比较？

**答：** 只要有一个字段的类型不可比较，例如切片、map、函数，整个结构体就不可比较，也不能做 map 的键。想比较内容就写 `Equal` 方法，或把不可比较的字段换成可比较的表示。

### 80. 为什么 map 里的结构体调不了指针接收者方法？

**答：** `m[k]` 不可寻址，编译器不能取它的地址来满足指针接收者。先把元素复制到一个变量，或者 map 里直接存指针。存指针之后要自己处理并发和 `nil`。

### 81. 多个嵌入类型有同名方法会怎样？

**答：** 外层类型如果没有自己的同名方法，提升后的名字冲突，选择这个名字会编译失败。必须显式选择某一层。字段名冲突同样如此。

### 82. `[]T` 能直接转成 `[]I` 吗？

**答：** 不能。元素类型不同，内存布局也不同：一边是具体值，一边是接口。要转换就建一个新切片，逐个把 `T` 放进接口。反过来，从 `[]I` 拿回 `T` 必须逐个断言。

### 83. 断言失败的两种写法差别是什么？

**答：** `v := i.(T)` 失败 panic。`v, ok := i.(T)` 失败时 `ok == false`，`v` 是零值，不 panic。库代码和解析外部数据时用第二种。

### 84. 值类型实现了接口，指针是不是也实现了？

**答：** `*T` 的方法集包含 `T` 的值接收者方法，所以值接收者实现的接口，`*T` 也实现。反过来不成立：只有指针接收者的方法时，`T` 没有实现该接口，`T` 的值不能赋给这个接口。

### 85. 方法表达式和方法值是什么？

**答：** 方法值把接收者绑死：`f := u.Write`，之后 `f(p)` 仍写到 `u`。方法表达式是函数，接收者变成第一个参数：`w := (*os.File).Write`，调用时 `w(f, p)`。方法表达式的类型跟接收者是 `T` 还是 `*T` 一致。

### 86. `error` 是接口吗？

**答：** 是。它只有一个方法：`Error() string`。任何有这个方法的类型都是 `error`。`nil` 错误必须是没有动态类型的 `nil` 接口，见第 69 题。

### 87. 嵌入指针和嵌入值有什么差别？

**答：** 嵌入 `T` 时，外层值包含一份 `T`，复制外层会复制这份 `T`。嵌入 `*T` 时，外层只含指针，复制外层后两边共享同一份 `T`；指针是 `nil` 时，调用提升方法会 panic。`sync.Mutex` 这类不能复制的字段，通常放在结构体里由外层指针使用，而不是把含锁的结构体按值传来传去。

### 88. 组合在代码里具体怎么写？

**答：** 小接口描述行为，结构体里嵌入或持有依赖，把调用转给它。需要改写一部分行为时，外层写同名方法，其余方法靠提升。测试时让假的结构体实现同一个小接口。不要为了“像继承”做多层嵌入。

## 5. 控制流、defer、panic

### 89. `switch` 会贯穿到下一个分支吗？

**答：** 不会。匹配到一个 `case` 并执行完就结束。要继续执行下一个分支必须显式写 `fallthrough`，而且它不检查下一个 `case` 的条件。`switch` 可以没有表达式，等价于 `switch true`，用来写一串条件。

### 90. `select` 的规则是什么？

**答：** 每个 `case` 是一次发送或接收。有多个可以立即进行时，伪随机选一个，不要假设顺序。有 `default` 且没有 case 能进行时走 `default`。某个 case 的 channel 是 `nil` 时，这个 case 永远不会被选中。没有任何 case、也没有 `default` 的 `select{}` 会永远阻塞。

### 91. `for` 有哪些形式？整数可以 range 吗？

**答：** 三种：`for cond {}`、`for init; cond; post {}`、`for range`。Go 1.22 起，在 `go 1.22` 或更高的语言版本下，可以对整数 range：`for i := range n` 产生 `0, 1, ..., n-1`。`n <= 0` 时循环不执行，不会 panic。`n` 只求值一次。

### 92. `break` 和 `continue` 怎么作用于外层循环？

**答：** 默认作用于最内层的 `for`、`switch` 或 `select`。要跳出外层循环，给外层加标签：

```go
Outer:
    for i := range 3 {
        for j := range 3 {
            if i == j {
                break Outer
            }
        }
    }
```

`continue` 的标签必须是循环。`break` 的标签可以是循环、switch 或 select。

### 93. `goto` 有什么限制？

**答：** 标签必须在同一函数内。不能跳过变量声明，从而让一个变量还没声明就被使用。不能跳进别的块里绕过它的声明。`goto` 能用，但多数时候 `break` 标签或拆函数更清楚。

### 94. `defer` 什么时候执行？顺序是什么？

**答：** 函数返回前执行，多个 `defer` 后进先出。`return` 的结果先写好，然后跑 `defer`，然后函数才真正回到调用方。`panic` 时已经注册的 `defer` 仍会执行。进程被 `os.Exit` 退出时不执行。

### 95. `defer` 的参数什么时候求值？

**答：** 登记 `defer` 时就求值，不是函数返回时。闭包内部的变量是执行时才读的。

```go
i := 0
defer fmt.Println(i) // 登记时 i 是 0
i++
defer func() { fmt.Println(i) }() // 返回时 i 是 1
// 输出先 1 后 0
```

### 96. `defer` 能修改返回值吗？

**答：** 能修改命名返回值，因为名字就是函数里的变量，`defer` 在返回值复制给调用方之前执行。非命名返回值在 `return expr` 时已经复制到一个临时结果，再改局部变量不会影响它。

```go
func f() (n int) {
    defer func() { n++ }()
    return 1 // 实际返回 2
}
```

### 97. 在循环里 `defer` 有什么问题？

**答：** `defer` 要到函数返回才执行，不是本轮循环结束就执行。循环里打开文件再 `defer close`，所有文件都会堆到函数结束，可能超出文件描述符限制。循环里要及时关闭，就放进一个独立函数，让 `defer` 在那次调用结束时运行，或者直接在循环末尾关闭并处理错误。

### 98. `panic` 和 `recover` 的规则是什么？

**答：** `panic` 停掉当前函数的正常执行，按 LIFO 跑 `defer`。`recover` 只有在 `defer` 函数里直接调用才接得住这次 panic，并返回传给 `panic` 的值。接住之后，当前函数正常返回，panic 不再向外传。

在普通流程里调用 `recover` 只会得到 `nil`。`panic(nil)` 的结果取决于语言版本：`go 1.21` 及以上默认让 `recover` 得到 `*runtime.PanicNilError`；`go 1.20` 及更早默认仍得到 `nil`。`GODEBUG=panicnil=1` 强制旧行为，`panicnil=0` 强制新行为。

### 99. 为什么 `recover` 包一层函数就失效？

**答：** 规范要求 `recover` 由 deferred 函数直接调用。deferred 函数再去调另一个函数，在那个函数里 `recover`，接不住。写成：

```go
defer func() {
    if v := recover(); v != nil {
        // 处理 v
    }
}()
```

### 100. `recover` 能接住别的 goroutine 里的 panic 吗？

**答：** 不能。panic 只沿当前 goroutine 的调用栈走。新 goroutine 如果 panic 又没有自己 `recover`，整个进程崩溃。每个 goroutine 的入口自己处理，或者用 `errgroup` 这类把错误传回来，不要用 panic 当跨 goroutine 的错误通道。

### 101. panic 之后后面的 `defer` 还会跑吗？某个 `defer` 又 panic 了呢？

**答：** 已经登记的 `defer` 都会按 LIFO 跑。如果其中一个再次 panic，这个新 panic 会替换正在传播的 panic，更早登记的 `defer` 继续执行。全部跑完后，若没有 `recover`，进程带着最后那次 panic 退出。

### 102. Go 1.22 的循环变量语义是什么？

**答：** 当 `go.mod` 的 `go` 版本是 1.22 或更高时，`for` 语句用 `:=` 声明的循环变量，每次迭代都是新变量。这包括 `for i := 0; i < n; i++` 和 `for i, v := range ...`。

变量声明在循环外面、循环里只用 `=` 时，仍是同一个变量。`go 1.21` 或更低的语言版本保持旧语义：整个循环共用一个变量。Go 1.26 没有 `GODEBUG=loopvar` 这个开关，不能靠它切回旧语义；要旧语义就保持较低的 `go` 行。

### 103. `range` 的副本语义怎么记？

**答：** 数组：见第 36 题。切片和字符串：复制头，不复制全部元素；值变量是每个元素或 rune 的副本。map：复制的是 map 头，键和值变量是副本，改值变量不会写回 map。channel：每次接收一个值，循环到 channel 关闭。整数：从 0 到 n-1 的新迭代变量。

### 104. 闭包放进循环启动 goroutine，现在还会踩循环变量吗？

**答：** 在 Go 1.22 及以上的语言版本里，`for _, v := range s { go func() { use(v) }() }` 每次的 `v` 是不同变量，goroutine 看到的是那一次的值。

旧语言版本里这是同一个 `v`，goroutine 可能全读到最后一次的值。修复办法在旧版本里是 `v := v` 或把 `v` 当参数传进函数。循环外声明的变量，两个版本都仍然共享。

## 6. 错误处理

### 105. 错误在 API 里怎么表示？

**答：** 普通失败用返回值，`error` 放在最后。调用方不能忽略错误再继续使用其他返回值，除非 API 明确说失败时其他值仍有定义。`nil` 表示成功。不要用 panic 表示参数不合法以外的、调用方能合理处理的情况。

### 106. `errors.New`、`fmt.Errorf` 和 `%w` 怎么用？

**答：** 静态文本用 `errors.New`。需要格式化用 `fmt.Errorf`。要保留底层错误、让 `errors.Is` 和 `errors.As` 找得到，用 `%w`。Go 1.20 起一条格式可以有多个 `%w`，也可以用 `errors.Join` 把多个错误收成一个。

只是把别人的错误文本拼进字符串、用 `%v`，调用方就拆不回来了。

### 107. `errors.Is` 和 `errors.As` 的差别是什么？

**答：** `Is` 沿着 `Unwrap()` 或 `Unwrap() []error` 看链上有没有一个错误等于目标，或实现了 `Is(error) bool` 并返回真。用来比较哨兵错误，例如 `io.EOF`。

`As` 找链上第一个能赋给目标类型的错误。目标必须是指向这个类型的非空指针：`errors.As(err, &pathErr)`，其中 `pathErr` 的类型是 `*os.PathError`。不要用类型断言只看最外层，包装后断言会失败。

### 108. `errors.Join` 和 `errors.AsType` 是什么？

**答：** `errors.Join` 从 Go 1.20 开始，把多个非 `nil` 错误合成一个，`Unwrap` 返回切片。`errors.Is` 和 `errors.As` 会按深度优先走进去。

`errors.AsType` 是 Go 1.26 加的泛型版本：

```go
e, ok := errors.AsType[*os.PathError](err)
```

它避免了 `As` 那个必须传指针的目标参数，类型不对时编译不过。

### 109. 哨兵错误、自定义错误类型、panic 分别适合什么？

**答：** 哨兵错误是包级变量，例如 `io.EOF`，调用方用 `errors.Is` 判断预期中的条件。需要附带数据时定义类型，例如路径和操作，调用方用 `errors.As` 或 `AsType` 取出。

panic 留给真正的违约：不变量被破坏、不可能到达的分支。`init` 或 `main` 里配置非法也可以 panic，因为程序无法继续。库的导出函数不要替调用方决定崩溃。

### 110. 为什么不要用 panic 做正常控制流？

**答：** panic 展开栈、执行 `defer`，成本高，而且调用方看签名不知道会 panic。跨 goroutine 还会直接搞垮进程。可预期的失败，包括校验、没找到、超时，都应该是 `error`。

### 111. 包装之后为什么不能用 `==` 比较错误？

**答：** `fmt.Errorf("open: %w", err)` 得到的是新的错误值，和原来的哨兵不是同一个值。`==` 只看最外层。要识别链上的哨兵，用 `errors.Is`。

### 112. 错误链怎样展开？

**答：** 实现 `Unwrap() error` 的是单链，实现 `Unwrap() []error` 的是多分支，`Join` 就是后者。`errors.Is` 和 `errors.As` 会走完整棵树。自己写循环时要处理这两种 `Unwrap`，否则会漏掉 `Join` 进去的错误。

### 113. 错误字符串有什么惯例？

**答：** 小写开头，结尾不加句号或换行，因为经常被包在别的句子里：`open config: no such file`。错误字符串不是给用户看的本地化文案，稳定的判断靠哨兵或类型，不靠比较字符串。

### 114. 名字以 `Must` 开头的函数是什么约定？

**答：** 失败就 panic，用在程序启动时就该失败的地方，例如 `regexp.MustCompile`、模板解析。请求路径上不要用 Must。对应地提供一个返回 `error` 的函数给需要处理失败的调用方。

## 7. 并发

### 115. goroutine 和操作系统线程有什么差别？

**答：** goroutine 是运行时调度的用户态协程，初始栈大约 2KB（`stackMin` 是 2048 字节），按需增长。线程栈是固定的一大块，创建和切换更重。一个 Go 进程里可以有远多于 CPU 数的 goroutine。goroutine 没有公开的 ID，不要用 ID 做业务逻辑。

### 116. GMP 里的 G、M、P 是什么？

**答：** G 是 goroutine。M 是执行 Go 代码的操作系统线程。P 是逻辑处理器，持有本地运行队列，个数等于 `GOMAXPROCS`。

M 必须绑定 P 才能执行 Go 代码。G 很多，M 可以多于 P：例如线程堵在系统调用里时，P 会被拿走交给别的 M。每个 M 还有一个 `g0`，在系统栈上做调度，不跑用户代码。

### 117. 调度时本地队列、全局队列、窃取和 netpoll 各做什么？

**答：** 新 goroutine 优先进当前 P 的本地队列。本地队列满了会把一半倒进全局队列。P 的本地队列空了，就先从全局队列拿，再从别的 P 偷一半。

网络连接设成非阻塞，goroutine 在读写上等待时挂到 netpoll，不占着 M。网卡就绪后 netpoll 把 G 放回运行队列。长时间堵在不可 netpoll 的系统调用里时，P 与这个 M 分离，另找 M 继续跑别的 G。

`sysmon` 不需要 P，负责抢占跑太久的 G、从 netpoll 取就绪事件、把长时间系统调用的 P 抢回来，以及在需要时触发强制 GC。

### 118. Go 的抢占是协作式还是异步的？

**答：** 早期主要在函数调用等安全点协作式让出，紧密循环可能长时间不让出。Go 1.14 起基于信号做异步抢占，Unix 上用 `SIGURG`，紧密循环也能被抢占。用户代码不要捕获或依赖 `SIGURG`。

### 119. goroutine 的栈有多大？怎样增长？

**答：** 从 Go 1.4 起，Go 代码使用的最小栈是 2048 字节，另外还会按平台加一小段系统保留。栈从 Go 1.3 起是连续的，不够时分配更大的一块并拷贝，不是分段栈。

64 位上默认上限是 `1000000000` 字节，约 1GB；32 位约 250MB。超过上限会崩溃。可以用 `runtime/debug.SetMaxStack` 调整。不要把“8KB 起步”再说成当前事实。

### 120. `GOMAXPROCS` 的默认值现在是什么？

**答：** Go 1.5 到 1.24，未设置时默认是 `runtime.NumCPU()`，也就是启动时看见的逻辑 CPU 数。

Go 1.25 起有两处变化。在 Linux 上，如果进程所在 cgroup 的 CPU bandwidth limit 比逻辑 CPU 数更小，默认用这个更小的限制；这对应容器的 CPU limit，不看 CPU request。在所有系统上，只要没有手动指定，运行时还会周期性地按 CPU 数或 cgroup 限制更新 `GOMAXPROCS`。

设置环境变量 `GOMAXPROCS`，或调用 `runtime.GOMAXPROCS(n)`（n > 0），会关掉这两种自动行为。`runtime.GOMAXPROCS(0)` 只查询当前值。`containermaxprocs=0` 和 `updatemaxprocs=0` 可以分别关掉上述两处。

### 121. 无缓冲和有缓冲 channel 的差别是什么？

**答：** 无缓冲 channel 的发送和接收必须相遇，发送才算完成。它用来交接和同步，不是用来堆数据。

有缓冲 channel 在缓冲区没满时发送不阻塞，缓冲区空时接收才阻塞。缓冲容量是资源上限，不是“随便写个 1 或 100”。缓冲满了发送方仍会阻塞。

### 122. channel 发送、接收、关闭的完整规则是什么？

**答：**

- 向 `nil` channel 发送或从它接收，永远阻塞。
- 向已关闭的 channel 发送会 panic。
- 从已关闭的 channel 接收，先把缓冲区里剩下的值读完，之后立即得到零值和 `ok == false`。
- 关闭 `nil` channel、或重复关闭，会 panic。
- `len` 和 `cap` 对 `nil` channel 得到 0。
- 关闭不是释放 channel 的条件。没有引用时 GC 会回收，不关闭也可以。

### 123. 应该由谁关闭 channel？

**答：** 由发送方关闭，并且只关闭一次。接收方不要关闭，否则会和发送方或其他接收方竞态。有多个发送方时，不要让每个发送方都 `close`；用 `WaitGroup` 等最后一个发送方结束再关闭，或者干脆不关闭，改用单独的“结束”信号。

### 124. `for range` channel 什么时候停？

**答：** 发送方 `close` 之后，缓冲区被读空，循环结束。没有人关闭，又没有新的发送，循环就永远堵在接收上。对 `nil` channel 做 `range` 会永远阻塞，一次都不进入循环体。range 不到“零值就结束”，因为零值可能是合法数据；要区分就用 `v, ok := <-ch`。

### 125. 单向 channel 有什么用？

**答：** `chan<- T` 只能发送，`<-chan T` 只能接收。函数参数写成单向，编译器帮你禁止用错方向。双向 channel 可以传给单向参数，反过来不行。关闭在类型系统里只允许发生在发送方那一侧。

### 126. `select` 里多个 case 同时就绪，选哪个？

**答：** 均匀地伪随机选择，不能写成“先写的优先”。要优先级就分成两个 select：先带 `default` 试高优先级，没有再进入会阻塞的 select。

`time.After` 放进 select 是超时的一种写法，热循环里的取舍见第 193 题。

### 127. 用 channel 做退出信号怎么写？

**答：** 关闭一个 `chan struct{}`，所有接收方同时醒来。不要往里面发送多次再指望每个 worker 收到一次，那是另一个模型。

```go
stop := make(chan struct{})
go func() {
    select {
    case <-stop:
        return
    case v := <-jobs:
        _ = v
    }
}()
close(stop)
```

已经关闭的 channel 上接收不会阻塞，所以 `<-stop` 适合当“已经取消”。

### 128. worker pool 的骨架是什么？

**答：** 一个 jobs channel，固定数量的 worker 从中取任务，结果送到另一个 channel 或就地处理。启动方负责在所有任务发送完后关闭 jobs。worker 用 `range` 退出。要限制排队长度就用有缓冲的 jobs，缓冲满时提交方被挡住，这是背压。

取消时带上 `context`，worker 在取任务和做任务两处都看 `ctx.Done()`。提前返回时要把还堵在发送上的 worker 放走，否则就是泄漏。

### 129. 扇出和扇入是什么？

**答：** 扇出是多个 goroutine 从同一个 jobs channel 取任务。扇入是多个结果 channel 由一个 goroutine 转发到同一个 channel。等全部输入都关闭后再关闭汇合后的 channel，可以用 `WaitGroup`。不要从多个 goroutine 关闭同一个 channel。

### 130. goroutine 泄漏通常是什么样子？

**答：** G 永远堵在 channel 发送或接收、`Mutex`、`WaitGroup` 或 `context` 没人取消的调用上，而没有任何路径再把它叫醒。常见写法是：往无缓冲 channel 发送，接收方提前 return，发送永久堵着。

Go 1.26 有实验性的 `goroutineleak` profile，用 `GOEXPERIMENT=goroutineleakprofile` 打开，也能挂到 `/debug/pprof/goroutineleak`。它借助 GC 的可达性判断“阻塞它的同步对象已经不可能被别的可运行 goroutine 碰到”。全局变量里的 channel 造成的泄漏它不一定看得见。这个 profile 默认还没开，计划在 Go 1.27 再考虑默认启用。

### 131. data race 是什么？怎么查？

**答：** 两个 goroutine 同时访问同一内存，至少一个是写，而且没有 happens-before 把它们排开，这就是 data race。Go 里 data race 的行为是未定义的，不保证“只是读到旧值”，也可能让程序出现更坏的结果。

`go test -race` 或 `go run -race` 用运行时检测实际发生的冲突。它有额外的 CPU 和内存开销，并且只能看到这次执行踩到的路径。修法是加锁、用 channel 交接所有权，或用 `sync/atomic` 做适合原子操作的计数和标志。

### 132. 哪些操作建立 happens-before？

**答：** 同一个 goroutine 里，语句按程序顺序排好。此外：

- 启动 goroutine 的 `go` 语句 happens-before 这个 goroutine 开始执行。
- channel 发送 happens-before 对应的那次接收完成。
- 无缓冲 channel 上，接收 happens-before 对应的发送完成。
- 容量为 C 的 channel 上，第 k 次接收 happens-before 第 k+C 次发送完成。
- `close` happens-before 因为关闭而收到零值的那次接收。
- `Mutex` 的第 n 次 `Unlock` happens-before 第 m 次 `Lock` 返回，n < m。
- `WaitGroup` 里把计数减到 0 的 `Done` happens-before `Wait` 返回。
- `sync/atomic` 的对齐原子操作也建立同步，细节在内存模型文档里。

没有这些关系的跨 goroutine 访问就是 race。`time.Sleep` 不建立 happens-before。

### 133. 为什么不能用 `Sleep` 做同步？

**答：** 睡着不代表另一个 goroutine 已经完成写入。调度一变，测试就时好时坏。要用 channel、锁、`WaitGroup` 或 `testing/synctest` 把“完成”表达出来。

### 134. `sync.Mutex` 能重入吗？能复制吗？

**答：** 不能重入。同一个 goroutine 连续 `Lock` 两次会死锁，因为锁没有所有者记录。未锁定时 `Unlock` 会 panic。

零值是未锁定状态，可以直接用。第一次使用之后不能复制，复制会把内部状态拷走，`go vet` 会对含 `noCopy` 的类型报警。锁应该放在结构体里，结构体通过指针传递。

### 135. `RWMutex` 有哪些限制？

**答：** 多个读者或一个写者。有写者在等待时，新的 `RLock` 会等待，避免写者饿死，所以读者不能递归加读锁。`RLock` 不能升级成 `Lock`，`Lock` 也不能降级成 `RLock`。使用后同样不能复制。

读锁只保护“在这次 `RLock` 到 `RUnlock` 之间，看到的数据没有写者在改”。把指针取出来再在锁外使用，保护就结束了。

### 136. `WaitGroup` 怎么用才不会提前返回或 panic？

**答：** 计数不能减成负数，否则 panic。`Wait` 看到计数是 0 就返回。因此这一批任务的 `Add` 必须在对应的 `Wait` 之前发生，通常在启动 goroutine 的那个 goroutine 里 `Add`，不要把 `Add` 放进子 goroutine 再和 `Wait` 赛跑。

`WaitGroup` 不能复制。复用同一组去做下一批任务时，要等上一次 `Wait` 已经返回。Go 1.25 的 `WaitGroup.Go(f)` 会自己 `Add(1)` 并在 `f` 正常返回后 `Done`；文档要求 `f` 不能 panic，panic 时它故意不 `Done`，避免 `Wait` 返回后和崩溃赛跑。Go 1.25 的 vet 分析器 `waitgroup` 会报告放错位置的 `Add`。

### 137. `sync.Once` 的语义是什么？panic 了会重试吗？

**答：** `Once.Do(f)` 保证 `f` 只被调用一次，并且所有 `Do` 都会等到这次调用返回。`f` 里再调用同一个 `Once` 会死锁。

`f` 如果 panic，`Do` 认为这次已经结束，以后的 `Do` 直接返回，不会再调用 `f`，也不会把 panic 重新抛出来。`sync.OnceFunc`、`OnceValue` 不同：失败后的每次调用都会用同一个值再次 panic。

### 138. `sync.Cond` 要注意什么？

**答：** `Wait` 必须在持有与 `Cond` 关联的锁时调用。`Wait` 会解锁、阻塞、被叫醒后再加锁。条件要写在循环里检查，因为叫醒可能是广播，条件未必已经成立。`Signal` 叫醒一个，`Broadcast` 叫醒全部。新代码很多时候用 channel 更直接；`Cond` 适合“锁保护的状态变了，叫醒等待者”。

### 139. `atomic` 和 `Mutex` 怎么选？

**答：** 单个计数、标志、指针发布，用 `sync/atomic`。Go 1.19 起有 `atomic.Int64`、`atomic.Pointer[T]` 这类类型，比直接用函数更不容易拿错位宽。

一块结构体要一起改、或者临界区里有多步不变量，用 `Mutex`。不要先原子读、再在锁外改、再原子写，那中间的状态别人看得到。`atomic.Value` 里 successive `Store` 的具体类型必须相同。

### 140. `sync.Pool` 是缓存吗？

**答：** 它是临时对象池，用来摊薄分配，不是通用缓存。池里的对象在 GC 时可能被清掉，`Get` 可能返回 `nil`，也可能返回别的 goroutine 刚 `Put` 的对象。取出来要重置状态，不能假设是干净的。

不要把数据库连接、文件这种必须归还的资源放进 Pool 就当连接池。`fmt` 的缓冲、临时 `bytes.Buffer` 才是典型用途。Pool 本身并发安全，里面的对象在拿出之后不是。

### 141. `errgroup` 在标准库里吗？它解决什么？

**答：** 不在标准库，在 `golang.org/x/sync/errgroup`。它在 `WaitGroup` 之上收集第一个返回的错误。`WithContext` 得到的 context 会在某个任务返回错误或父 context 取消时取消。`SetLimit` 限制同时运行的任务数。

任务要响应 context。组不负责接住 panic。

### 142. `context` 的取消怎样传播？

**答：** 取消父 context，从它派生的子 context 都会取消。取消子 context 不影响父，也不影响兄弟。`Done()` 在取消后被关闭。`Err()` 在取消前是 `nil`，之后是 `context.Canceled` 或 `context.DeadlineExceeded`。

`WithCancel`、`WithTimeout`、`WithDeadline` 都返回取消函数。即使超时已经到了，也要调用它，以便释放定时器资源。请求结束时用 `defer cancel()`。

### 143. `WithTimeout`、`WithDeadline`、`WithCancelCause` 的差别是什么？

**答：** `WithCancel` 只手动取消。`WithDeadline` 在某个时间点取消，`WithTimeout` 是从现在起经过一段时长，内部就是 Deadline。Cause 系列从 Go 1.20/1.21 起可以附带取消原因，`context.Cause` 取出。原因不会替换 `ctx.Err()` 的那两个哨兵，调用方仍用 `errors.Is` 判断超时或取消，需要细节时再看 Cause。

### 144. `context.Value` 应该放什么？

**答：** 只放请求范围的数据，例如请求 ID、认证后的身份。不要用它代替函数参数。键用未导出的类型，避免和其他包的字符串键撞车。`Value` 查找是沿着父链走的，不是一个并发 map，不要拿它当会话存储。

### 145. `context` 可以存在结构体里吗？

**答：** 官方建议不要存。每个需要它的函数把 `ctx` 放在第一个参数，名字就叫 `ctx`。例外是接口已经定死、方法签名里没有 context，而对象的生命周期确实等于一次请求，例如一些客户端选项。`http.Request` 自己带着 context，用 `r.Context()`，不要再复制一份到处存。

不要把 `context.Background()` 或 `TODO()` 写进请求路径后就不再替换。`Background` 用于 `main`、初始化和测试的根。`TODO` 表示这里本该有上下文，但调用链还没接上。

## 8. 内存、GC 与调度细节

### 146. 逃逸分析是什么？

**答：** 编译器判断一个变量的引用会不会在函数返回后还被使用。不会，就放在栈上；会，就分配到堆上，交给 GC。栈分配随函数返回释放，不增加 GC 压力。

`go build -gcflags='-m'` 可以打印逃逸结论。结论会随编译器版本变，不要为了和某一版的日志完全一致而把代码写歪。

### 147. 哪些写法容易逃逸？

**答：** 返回局部变量的指针、把局部变量放进接口、放进 channel、存在全局或堆上的结构里、闭包引用了它且闭包本身逃逸、切片或 map 被追加后还被外部持有。大对象不一定逃逸；小对象只要生命周期超出函数就会逃逸。接口调用经常让具体值逃到堆上。

### 148. 栈是怎样增长的？

**答：** 连续栈。函数序言发现栈空间不够时，分配一块更大的栈，把旧内容拷过去，并修正栈上的指针。从 Go 1.3 起不再使用分段栈。用户不用自己 `malloc` 栈。深递归或在栈上放很大的数组会把栈撑大，直到第 119 题的上限。

### 149. Go 的 GC 在用户可见的层面上是什么样？

**答：** 并发的三色标记-清除，不整理，不分代。对象是白、灰、黑：白是未访问，灰是已发现但子指针还没扫，黑是扫完。标记和用户 goroutine 并发进行，清除大多也是增量的。

因为不移动对象，指针不会因为 GC 被改写，碎片靠按 size class 分配来控制。Go 1.26 默认换成 Green Tea 收集器，它改进小对象标记和扫描的局部性，并在较新的 amd64 上用向量指令扫小对象。这没有把 GC 改成整理式或分代式。可用 `GOEXPERIMENT=nogreenteagc` 关掉，这个开关预计在 Go 1.27 去掉。

### 150. 写屏障是做什么的？

**答：** 标记和程序并发时，用户代码可能把一个白色对象挂到黑色对象下面，如果没有别的灰色对象还指着它，它就会被漏掉。写屏障在指针写入时把相关对象标灰。

Go 1.8 起用混合写屏障，结合 Dijkstra 的插入屏障和 Yuasa 的删除屏障，栈可以按灰色处理，从而避免每轮 GC 结束时长时间停下来重扫所有栈。

### 151. `GOGC` 和 `GOMEMLIMIT` 分别控制什么？

**答：** `GOGC` 默认 100，表示相对上一轮结束后的存活堆，再分配大约 100% 就触发下一轮，堆大约翻倍。调高减少 GC 频率、提高内存占用；调低相反。`GOGC=off` 关掉按增长比例触发。

`GOMEMLIMIT` 从 Go 1.19 开始，是堆的软上限。接近上限时 GC 会更积极。它不是硬保证：存活数据本身超过上限时仍会占用那么多内存。一般按容器内存限额留出一部分给栈、操作系统和其他进程来设置。

### 152. 什么时候会触发 GC？

**答：** 堆分配达到 `GOGC` 对应的目标时；接近 `GOMEMLIMIT` 时；运行时也会在距离上一轮超过约 2 分钟（`forcegcperiod`）后强制一轮，避免完全不分配的程序永远不回收。`runtime.GC` 可以手动触发，一般只出现在测试和基准里。

### 153. 现在还有 Stop-The-World 吗？

**答：** 有，但是短暂停，用来做标记开始和标记终止这类必须全局一致的步骤。标记本身和用户代码并发。Go 1.8 之后不再为了重扫所有栈做一次长停顿。业务延迟毛刺如果来自 GC，要用 trace 和 GC 日志确认，而不是假定“并发 GC 就没有任何停顿”。

### 154. 标记辅助是什么？

**答：** GC 跟不上分配速度时，分配的 goroutine 会被要求帮着做一部分标记工作，把分配和标记绑在一起，避免堆无限制长。这会表现为请求延迟偶尔变高。缓解办法是减少分配、调 `GOGC`，或在内存允许时提高 `GOMEMLIMIT` 的空间。

### 155. `SetFinalizer` 和 `AddCleanup` 怎么选？

**答：** `runtime.SetFinalizer` 旧，一个对象只能有一个 finalizer，对象成环时可能一直不执行，也不能挂在内部指针上。执行时机不确定，进程退出前不保证运行。

Go 1.24 的 `runtime.AddCleanup` 可以给一个对象挂多个清理函数，可以挂在内部指针上。对象互相引用形成环时，清理仍然可以运行，顺序没有保证，也不会为了等清理而推迟释放对象。新代码用 `AddCleanup`。清理函数或它的参数如果还能到达这个对象，对象就收不掉，清理也不会跑；参数如果就是这个指针本身，`AddCleanup` 会直接 panic。大小为 0 的对象不保证会跑清理，因为它可能和其他零大小对象共用地址。清理函数应尽快返回，重活放到别的 goroutine。进程退出前不保证执行，不要用它做必须成功的业务提交。

### 156. `weak.Pointer` 是什么？

**答：** Go 1.24 的 `weak` 包提供弱指针。它不阻止对象被回收。`Value()` 在对象还活着时返回普通指针，已经被回收时返回 `nil`。适合做缓存、规范化表这类“没人用就可以消失”的索引。对象真正的资源释放仍要配 `AddCleanup` 或显式 `Close`。弱指针自己可比较，身份在目标回收之后仍然稳定。

### 157. 内存分配器大致分几层？

**答：** Go 1.26 里，页大小是 8KB。不超过 32KB 的小对象按 size class 分配；大于这个的直接向堆要。不含指针且小于 16 字节的对象可以进 tiny 分配器，多个拼在一个 16 字节块里。

每个 P 有 `mcache`，从自己的缓存取小对象时不加全局锁。某种 size class 用完了再向 `mcentral` 要 span。`mheap` 管理页和向操作系统申请、归还。这些名字是实现结构，面试说出“每 P 缓存、中央空闲链表、全局堆”这三层即可。

### 158. 怎样看分配和 goroutine 卡在哪？

**答：** 标准库 `net/http/pprof` 或 `runtime/pprof`。CPU profile 看函数耗时，heap profile 看谁在分配，goroutine profile 看卡在哪个调用栈。Go 1.26 里 `go tool pprof -http` 默认打开火焰图。

`go test -benchmem` 看每次操作的分配次数和字节数。trace（`runtime/trace` 或 `go test -trace`）用来看调度、GC 和系统调用的时间线，不是用来替代 profile。

### 159. 减少分配的常见做法是什么？

**答：** 切片预留容量，避免循环里 `append` 扩容。字符串拼接用 `strings.Builder`。热路径上不要把具体类型反复放进接口。可以复用的临时缓冲放进 `sync.Pool`，取出来后 `Reset`。让 API 接收 `[]byte` 缓冲并由调用方提供，而不是每次返回新切片。先用 pprof 找到分配点再改，不要凭感觉把所有东西改成数组。

### 160. `sync.Pool` 和 GC 的关系是什么？

**答：** GC 发生时，Pool 里上一轮放进去、还没取走的对象可以被丢掉。所以 Pool 降低的是稳态分配速率，不保证对象一直留着，也不能用来限制内存上限。对象被丢掉后下次 `Get` 会重新分配，这是预期行为。

### 161. 指针多对 GC 有什么影响？

**答：** 标记要扫描指针。不含指针的对象可以跳过扫描，tiny 分配器也只收这类对象。大的 `[]byte` 比装了很多指针的结构更便宜扫。不要为了这个把清晰的数据结构改成手工索引；分配次数通常比“多一个指针”更值得先优化。

### 162. Green Tea 改变了哪些面试答案？

**答：** 它是 Go 1.25 的实验，Go 1.26 起默认开启。官方给出的预期是，在大量使用 GC 的程序里，GC 开销大约下降 10% 到 40%，新一点的 amd64 上扫描小对象还可以再用向量指令再降一截。

三色标记、写屏障、`GOGC`、`GOMEMLIMIT`、逃逸分析这些答案不用改。不要把 Green Tea 描述成换了一套用户可见的内存模型。

## 9. 泛型与版本差异

### 163. 泛型从哪一版开始？基本写法是什么？

**答：** Go 1.18。类型参数写在函数或类型名后面的方括号里：

```go
func Map[S ~[]E, E any](s S, f func(E) E) S {
    out := make(S, len(s))
    for i := range s {
        out[i] = f(s[i])
    }
    return out
}
```

调用时类型参数多数能从实参推断。不能推断时显式写出 `Map[[]int, int](s, f)`，或者只写编译器推不出的那部分。

### 164. 约束、`~` 和联合类型是什么？

**答：** 约束是接口，描述类型参数允许的类型集合。`~[]E` 表示底层类型是 `[]E` 的所有类型，包括 `type MySlice []E`。没有 `~` 时，具名类型往往不满足约束。

联合用 `|`：`interface{ ~int | ~string }`。一个类型参数可以同时要求方法和类型集合。普通接口做约束时，类型参数上只能调用约束里有的方法。

### 165. `any` 和 `comparable` 做约束时表示什么？

**答：** `any` 对类型没有要求。`comparable` 表示可以用 `==` 和 `!=`，能做 map 的键。Go 1.20 起 `comparable` 也包含接口这类“可能在运行时比较失败”的类型；用不可比较的动态类型真去比较，仍会 panic。切片、map、函数不满足 `comparable`。

### 166. 方法可以有自己的类型参数吗？

**答：** 不可以。类型参数属于类型或函数。方法不能再声明一套属于自己的类型参数。需要额外的类型参数就写成函数，或者把参数提升到接收者的类型上。

### 167. 泛型和接口怎么选？

**答：** 同一份算法要用于多种具体类型、并且调用方在编译期就知道类型时，用泛型。不同实现要在运行时替换、或放进同一个容器时，用接口。两者经常一起用：泛型函数的参数类型约束成一个小接口。

不要为了“以后可能有第二种类型”先引入类型参数。

### 168. `slices`、`maps`、`cmp` 提供了什么？

**答：** 三者都从 Go 1.21 进入标准库。`slices` 有排序、二分、`Clone`、`Equal`、`Contains`、`Grow`、`Clip`、`Delete` 等。`maps` 有 `Clone`、`Copy`、`Equal`、`Keys`、`Values`。Go 1.23 起 `maps.Keys` 这类函数返回迭代器。`cmp` 提供 `Ordered` 约束以及 `Compare`、`Less`。

`slices.Clip` 不复制数据，只把容量收成长度，见第 35 题。

### 169. `clear`、`min`、`max` 从哪一版可以放心用？

**答：** Go 1.21。更老的语言版本里这些是普通标识符，不是内建。模块的 `go` 行低于 1.21 时，即使用新工具链编译，也不能使用这些新语法。

### 170. Go 1.22 有哪些语言变化现在还会考？

**答：** 循环变量改为每次迭代一份，见第 102 题。可以对整数 `range`。另外工作区里的 vendor 和一些工具链细节有变化，但面试主线是前两条。语言版本由 `go.mod` 的 `go` 行决定，不是由机器上的工具链版本单独决定。

### 171. Go 1.23 的 range-over-func 是什么？

**答：** `for` 可以遍历函数迭代器。标准库 `iter.Seq[V]` 是 `func(yield func(V) bool)`，`iter.Seq2[K, V]` 是 `func(yield func(K, V) bool)`。

```go
func count(n int) iter.Seq[int] {
    return func(yield func(int) bool) {
        for i := range n {
            if !yield(i) {
                return
            }
        }
    }
}
```

`yield` 返回 false 表示调用方停止了（`break`、`return` 或 panic）。迭代器必须停下来，不能再调用 `yield`。再调用会 panic。循环变量的语义和第 102 题一致。

### 172. `unique` 包做什么？

**答：** Go 1.23 加入。`unique.Make(v)` 返回一个可比较的 `Handle[T]`，内容相同的值会得到同一个句柄，适合做长期存在的字符串或结构的规范化，减少重复副本。句柄可以做 map 的键。Go 1.25 起内部会更积极地回收已经没人用的值。它不是 `sync.Map`，也不保证进程里永远只有一份，没人引用后可以被收掉。

### 173. Go 1.24 有哪些现在已经稳定的变化？

**答：** 泛型类型别名可用。内置 map 改为 Swiss Table。`weak` 和 `runtime.AddCleanup` 可用。`testing.B.Loop` 作为基准循环，比手写 `b.N` 更不容易把编译器优化写错。`os.Root` 把文件操作限制在某个目录下面。`go get` 的工具链管理也有配套变化。面试里和语义最相关的是 map 实现、弱指针和 cleanup。

### 174. Go 1.25 有哪些面试会碰到的变化？

**答：** `GOMAXPROCS` 开始感知 cgroup CPU limit，并会自动更新，见第 120 题。`testing/synctest` 稳定：`synctest.Test` 在一个气泡里跑测试，时间是假的，所有 goroutine 都阻塞时时间向前跳。`Wait` 等到气泡里的 goroutine 都堵住。

`encoding/json/v2` 和 `encoding/json/jsontext` 仍是实验，要 `GOEXPERIMENT=jsonv2`。Green Tea GC 在 1.25 是实验，1.26 才默认。`WaitGroup.Go` 在这一版可用。

### 175. Go 1.26 的语言变化是什么？

**答：** 两处。`new` 可以接收表达式作为初值，见第 8 题。泛型类型可以在自己的类型参数列表里引用自己，从而写出递归约束：

```go
type Adder[A Adder[A]] interface {
    Add(A) A
}
```

这在 1.25 及以前是不允许的。运行时方面，Green Tea 默认开启，cgo 调用开销下降，64 位上堆基址会随机化。`errors.AsType` 进入标准库。

Go 1.26 的发布说明写过 `go mod init` 会把 `go` 行写成上一版。Go 1.26.1 的实现不是这样：`cmd/go` 里 `CreateModFile` 调用 `gover.Local()`，本机实际写出的是 `go 1.26.1`。要让模块停留在上一版语言语义，需要自己改这一行。

### 176. `go` 版本行怎样影响编译结果？

**答：** `go.mod` 里的 `go 1.N` 选择语言版本。用 Go 1.26 的工具链编译 `go 1.21` 的模块，仍会拒绝 1.22 的整数 range，并使用旧的循环变量语义。标准库的一些行为也按这个版本选默认，例如定时器 channel。升级工具链不等于升级语言版本；改 `go` 行才是。

### 177. 迭代器写错会怎样？

**答：** 调用方 `break` 之后，`yield` 返回 false。迭代器如果继续调用 `yield`，运行时会 panic。迭代器如果在返回 false 后还去修改已经交给调用方的共享数据，语义就和“循环已经结束”矛盾。把迭代器写成阻塞、或者在 `yield` 里回调用户代码再重入同一个迭代器，都容易死锁或重复遍历。

### 178. 泛型会降低性能吗？

**答：** 编译器按实例化后的具体类型生成代码，和手写一份具体类型接近，没有接口调用的间接。约束是接口、函数体里通过接口方法调用时，那一次调用仍是接口调用。代码体积会随实例化份数增加。先写清楚，再看 pprof，不要为了想象中的开销退回 `interface{}`。

## 10. 模块、测试与标准库

### 179. `go.mod` 和 `go.sum` 各记什么？

**答：** `go.mod` 记模块路径、语言版本、依赖及选定的版本。`go.sum` 记这些模块内容的密码学校验，防止下载到被换掉的源码。`go.sum` 不是“锁定传递依赖”的唯一文件，选定版本在 `go.mod` 的 `require` 里。构建时校验失败就停止，不要删掉 `go.sum` 来“修”构建。

### 180. `replace`、`exclude`、`retractions` 做什么？

**答：** `replace` 把某个模块换成另一个路径或版本，常用于本地联调。它只对当前模块生效，你发布出去后，依赖你的人不会继承这个 `replace`。

`exclude` 让选择算法跳过某个版本。作者在新版本里收回一个已发布版本时用 retract，别人的构建会避免自动选到它，但已经写进 `go.mod` 的版本不会被偷偷改掉。

### 181. `GOPROXY`、`GOSUMDB`、vendor、workspace 分别是什么？

**答：** `GOPROXY` 是模块下载代理，默认 `proxy.golang.org,direct`。`GOSUMDB` 是校验和数据库，用来核对 `go.sum`。内网不能访问公共代理时，应设自己的代理和 sumdb，而不是用 `GOSUMDB=off` 把校验关掉。

`go mod vendor` 把依赖放进仓库，构建时 `-mod=vendor` 不再访问网络。`go.work` 把本地多个模块组成工作区，适合同时改两个模块。库的发布构建不要依赖开发者机器上的 `go.work`。

### 182. 主版本 v2 及以上的模块路径有什么要求？

**答：** 模块路径必须以 `/v2`、`/v3` 结尾，import 路径也带这个后缀。v0 和 v1 不带后缀。v2 如果还用 v1 的路径，就是另一个不兼容的模块被放错了位置，语义化版本的选择算法会乱。

### 183. build tags 和 `//go:embed` 怎么用？

**答：** 文件第一行附近写 `//go:build linux && amd64`。旧的 `// +build` 仍能识别，新代码只用 `//go:build`。标签可以表示系统、实验或自己定义的条件，测试用 `-tags` 打开。

`//go:embed` 把文件或目录打进二进制。变量类型是 `string`、`[]byte` 或 `embed.FS`。模式不能是绝对路径，也不能含 `..`。要嵌入，包需要导入 `embed`，哪怕只是 `import _ "embed"`。嵌入在编译期完成，换文件必须重新编译。

### 184. 表格驱动测试怎么写？

**答：** 用一个切片存放名字、输入和期望。循环里 `t.Run`，每个子测试独立失败。比较错误用 `errors.Is`，比较切片用 `slices.Equal`，不要用 `==`。需要并发时在子测试里 `t.Parallel()`，注意第 187 题。

### 185. 基准测试用 `b.N` 还是 `b.Loop`？

**答：** Go 1.24 起优先用 `for b.Loop() { ... }`。它由测试框架控制迭代，并避免编译器把循环整个优化掉。`b.N` 仍然有效：函数会以不同的 `b.N` 被调用多次，循环里不要自己重置计时器以外的重活，准备数据放在 `b.ResetTimer()` 之前。

Go 1.26 之前，`b.Loop` 会阻止循环体里的函数内联，基准因此可能多出本来会被优化掉的分配，测得偏慢。1.26 起不再阻止内联。循环里的参数、结果和被赋值的变量仍然保持存活，避免编译器把整段基准优化掉。报告里用 `-benchmem` 看分配。计时包含循环内的所有代码，不要在循环里打印。

### 186. fuzz 测试测什么？

**答：** Go 1.18 起，`func FuzzXxx(f *testing.F)` 先用 `f.Add` 放种子，再 `f.Fuzz` 接收随机输入。它用来找解析器、解码器和边界处理的崩溃与往返不一致。fuzz 不是功能测试的替代，种子应该覆盖你已经知道的例子。语料默认放在 `testdata`。

### 187. `t.Parallel` 有什么注意点？

**答：** 子测试并发执行，不能依赖顺序，也不能共用一个可变的全局，除非测试自己加锁。循环里对子测试使用并行时，用 `t.Run` 传入的 `t`，不要在子测试里用外层的 `t`。

Go 1.22 之前还要避免循环变量被所有子测试共享。`t.Setenv` 不能和并行测试一起用，因为它改的是进程级环境变量。

### 188. Example 测试怎样算通过？

**答：** 函数名以 `Example` 开头，可以是 `Example`、`ExampleF` 或 `ExampleT_M`。注释里写：

```go
func ExampleHello() {
    fmt.Println("hi")
    // Output:
    // hi
}
```

标准输出必须和 `Output` 完全一致。没有 `Output` 的 Example 只编译、不比较输出。它同时是文档里的可运行例子。

### 189. `-race` 和覆盖率怎么用？

**答：** `go test -race ./...` 检测这次跑到的 data race。`go test -cover` 看语句覆盖率，`-coverprofile` 再生成报告。覆盖率高不代表并发和错误路径被测到。竞态检测不能和某些不支持的平台组合，失败时以工具链的说明为准。

### 190. `http.Server` 为什么必须设置超时？

**答：** 零值超时表示不限制。客户端可以慢慢发头或身体，占着连接和 goroutine。至少设置 `ReadHeaderTimeout`、`ReadTimeout`、`WriteTimeout` 和 `IdleTimeout`。`ReadTimeout` 从开始读请求算起，期限包含请求体。`ReadHeaderTimeout` 只限制读请求头。头读完后，如果 `ReadTimeout` 非零，读截止时间会改到从请求开始算的那个时刻；`ReadTimeout` 为零则会清掉截止时间，请求体不再受服务器读超时限制。需要按请求决定请求体期限时，在 handler 里用 `r.Context()` 再包 `context.WithTimeout`。

`http.ListenAndServe` 用的是零值超时的服务器，公开服务不要直接用它。`http.DefaultClient` 也没有超时，调用外部接口时用自己的 `http.Client`，设置 `Timeout` 或给每个请求加 context。

### 191. 为什么要关闭 `http.Response.Body`？

**答：** 不关闭、也不读完，底层连接不能回到连接池，后续请求会一直新建连接。客户端应：

```go
defer resp.Body.Close()
_, _ = io.Copy(io.Discard, resp.Body)
```

先读完再关闭，连接才能复用。`Close` 的错误在这里通常无法恢复，真正的读写错误来自 `Copy` 或 `Read`。服务端的 `r.Body` 由服务器关闭，handler 不必 `Close`，但读的时候仍要处理错误。

### 192. `encoding/json` 有哪些经典坑？

**答：** 解到 `interface{}` 时，JSON 数字变成 `float64`，大整数会丢精度。需要原文就用 `Decoder.UseNumber()`。未知字段默认忽略；`Decoder.DisallowUnknownFields` 可以拒绝。

`omitempty` 在 v1 里省略零值：`false`、`0`、`""`、`nil` 指针、`nil` 切片和 `nil` map。空结构体不是“空”，不会被省略。`nil` 切片编成 `null`，空切片编成 `[]`。要区分“没传”和“零值”，用指针或 `json.RawMessage`。

v1 解结构体时优先精确匹配字段名或 tag；没有精确匹配时才做大小写不敏感的匹配。这些都是 v1 的行为。v2 实验实现把 `omitempty`、`nil` 切片和大小写匹配改了，不要混在默认 JSON 的答案里。

### 193. `time.Time` 为什么不能都用 `==`？`time.After` 还会泄漏吗？

**答：** `Time` 里有墙上时钟、时区位置和可能存在的单调时钟读数。`==` 会把这些都比进去，两个表示同一瞬间的时间可能不相等。比较瞬间用 `t.Equal(u)`。`Sub` 在两边都有单调读数时用单调时钟，避免墙上时钟回拨。序列化会丢掉单调读数。

Go 1.23 之前，`time.After` 或 `NewTimer` 创建的计时器如果没触发也没 `Stop`，GC 不会收，循环里反复 `select` + `time.After` 会堆积。`go 1.23` 及以上默认改成：未被引用的计时器即使没 `Stop` 也能回收；channel 按同步通道使用，`Stop` 或 `Reset` 之后不会再读到旧时间。这个默认值跟着 `go` 行走，`GODEBUG=asynctimerchan=1` 可以暂时回到旧行为，Go 1.27 预计去掉。

热路径上仍建议用 `NewTimer`，在循环里 `Reset`，因为每次 `time.After` 仍会分配。需要提前取消等待时调用 `Stop`。

### 194. `math/rand` 和 `crypto/rand` 怎么选？

**答：** 模拟、抖动、测试用 `math/rand/v2`。Go 1.20 起全局 `math/rand` 会自动播种，不再是写死的 `Seed(1)`，但它仍然不是密码学安全的。密钥、token、随机 ID 用 `crypto/rand`。

Go 1.26 起，`crypto/ecdsa`、`crypto/rsa` 等若干 `GenerateKey` 忽略传入的 `io.Reader`，总是用安全随机源。测试要确定性随机数时用 `testing/cryptotest.SetGlobalRandom`。`GODEBUG=cryptocustomrand=1` 只是临时恢复旧行为。

### 195. `database/sql` 里最容易漏什么？

**答：** `Query` 返回的 `Rows` 必须 `Close`，否则连接不会回到池里。`defer rows.Close()` 放在确认 `err == nil` 之后。循环 `Next` 结束后还要看 `rows.Err()`。`Scan` 的目标和列类型要匹配。

不要在循环里反复 `Open` 数据库；`sql.DB` 就是池，应长期持有，并发安全。`DB.Query` 使用的语句会由库关闭，自己 `Prepare` 的 `Stmt` 要自己关。context 用 `QueryContext`，取消时查询能停下来。

### 196. `log/slog` 和 `log` 的差别是什么？

**答：** `log` 打一行文本。`slog` 从 Go 1.21 开始，记录带级别和键值属性的结构化日志，由 `Handler` 决定写成文本还是 JSON。级别不够时 `Enabled` 可以避免白做格式化。把请求 ID 放进 `slog.Logger` 的 `With`，而不是塞进 `context.Value` 再到处取。Go 1.26 增加了 `NewMultiHandler`，把一条记录交给多个 handler。

日志里不要放密钥和完整的个人数据。错误用 `slog.Any("err", err)` 或包装后的属性，保留错误链。

### 197. 正则应该在哪里编译？

**答：** `regexp.Compile` 的结果可以并发使用。把 `MustCompile` 放在包级变量或 `sync.Once` 里，不要在每个请求里编译同一条表达式。不可信的正则可能带来灾难性回溯，不要直接编译用户给的任意模式去匹配不受长度限制的输入。

### 198. `defer` 关闭文件时怎样处理 `Close` 的错误？

**答：** `Close` 可能在刷新时失败，尤其是写文件。只 `defer f.Close()` 会把这个错误丢掉。写路径上在函数返回前显式 `Close`，如果还没有别的错误，就返回 `Close` 的错误：

```go
func write(path, data string) (err error) {
    f, err := os.Create(path)
    if err != nil {
        return err
    }
    defer func() {
        cerr := f.Close()
        if err == nil {
            err = cerr
        }
    }()
    _, err = f.WriteString(data)
    return err
}
```

只读文件的 `Close` 失败较少成为业务结果，仍要关掉，避免描述符泄漏。

### 199. cgo 的代价是什么？

**答：** 调用要切换到 C 的调用约定，当前 goroutine 会占住一个操作系统线程直到 C 函数返回。C 函数阻塞会占着 M，运行时可能再开线程。频繁的细碎 cgo 调用比调用本身做的事还贵。

Go 指针传给 C 有一套规则：C 不能长期保存 Go 指针，也不能把 Go 指针写进 Go 没分配的内存。破坏这些规则会在运行时检查里崩溃。能用纯 Go 实现时就不要为了小函数走 cgo。Go 1.26 降低了 cgo 调用的固定开销，大约 30%，但跨边界的成本还在。

### 200. 线上 Go 进程出了问题，先看哪几样？

**答：** 先看症状再选工具，不要一上来改 `GOGC`。

- 结果时对时错、只在多核出现：用 `-race` 复现，或检查共享 map、共享切片头和没加锁的结构体。
- CPU 高：CPU profile。内存涨：heap profile，同时看是分配速率高还是存活对象多。goroutine 数涨：goroutine profile，看堵在哪个 channel 或锁。
- 延迟周期性变长：trace，看是不是 GC 标记、辅助标记或调度。
- 容器里并发度异常：看实际 `GOMAXPROCS`，Go 1.25 起它可能跟着 CPU limit 走。
- 行为像旧版本：看 `go.mod` 的 `go` 行和 `GODEBUG`。很多兼容开关，例如 `panicnil`、`asynctimerchan`，会改变第 98、193 题里的行为。

`GODEBUG=gctrace=1` 能看每轮 GC 的时间和堆大小。pprof 的 HTTP 端点不要暴露到公网。
