# 最小链设计

日期：2026-10-29

一条内存里的转账链。进程 A 出块。进程 A 和进程 B 都接受用户交易。B 把块从 A 拉过去，两边对同一批转账算出同一个状态根。对应学习计划阶段 2。

## 不做

EVM、智能合约、gas、点对点节点发现、持久化数据库、Merkle Patricia Trie、EIP-155。不依赖 go-ethereum。只有 A 出块，B 不出块，也不做分叉选择。

## 字节编码

整数用大端。十六进制在 JSON 里用小写，可以带 `0x` 前缀。

交易的签名原文是 36 字节：

```text
to      20
value   uint64
nonce   uint64
```

交易的规范字节是 101 字节：签名原文再接 65 字节签名。

区块哈希的原文是：

```text
parentHash   32
stateRoot    32
txCount      uint32
txs          每笔交易的 101 字节规范形式，顺序与区块里一致
```

没有交易时，`txCount` 为 0，后面不跟交易字节。

## 签名与地址

演示私钥（公开测试向量，写在代码和 README 里）：

```text
ac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80
```

地址算法：未压缩公钥 65 字节，第一字节是 `0x04`。对去掉这个前缀后的 64 字节做 Keccak-256，取最后 20 字节。该私钥的地址是 `f39fd6e51aad88f6f4ce6ab8827279cfffb92266`。

签名是 `ecdsa.SignCompact(priv, keccak256(签名原文), false)` 的 65 字节结果，布局为 `header || R || S`。`header` 为 27 或 28。校验用 `ecdsa.RecoverCompact`。

`sig.Verify(address, hash, signature)` 成功的条件是：恢复没有错误，且恢复出的地址等于 `address`。合法签名通过。把签名第 11 个字节（下标 10）异或 `0x01` 后，恢复出的地址变了，`Verify` 返回错误。

## 数据结构

账户：20 字节地址、`uint64` 余额、`uint64` nonce。

已签名交易：收款地址、金额、nonce、65 字节签名。发送方不放进交易里，由签名恢复。

区块：高度、父哈希、交易列表、状态根，以及由「字节编码」算出的哈希。

创世块高度为 0，父哈希为 32 个 0。交易列表为空。状态里只有演示账户，余额 `1000000`，nonce `0`。A 和 B 都在代码里带同一份创世块，B 不需要把创世块从 A 拉下来。

## 状态根

把账户按地址字节升序排列。每个账户编码为 36 字节：地址、余额、nonce。状态根是这段拼接的 Keccak-256。

空账户列表的根是 Keccak-256(空字节)，即 `c5d2460186f7233c927e7db2dcc703c0e500b653ca82273b7bfad8045d85a470`。

`Put` 插入或覆盖。`Delete` 删掉账户；删除不存在的账户不改变根。余额变成 0 不会自动删除。插入、修改、删除之后根会变。同一批账户无论以什么顺序放入，根都相同。

## 交易池

池按当前账户状态准入。账户不存在时，nonce 和余额都按 0。

拒绝：

- `ErrBadSignature`：签名长度不是 65，或 `RecoverCompact` 返回错误。测试把 `header` 改成 `0`。
- `ErrNonceTooLow`：交易 nonce 小于该账户当前 nonce。
- `ErrInsufficientBalance`：交易金额大于该账户当前余额。只和账户里已有的余额比，不扣除池中其他待处理交易。

同一发送方、同一 nonce 再进一次，拒绝，错误是 `ErrNonceUsed`。nonce 大于当前值的交易可以进池。

`Pending` 的顺序是发送方地址升序，同一发送方再按 nonce 升序。

`Drop(sender, nonce)` 从池里删掉这一笔。区块接受成功后，块里的每一笔都从本机池里删掉。

## 执行

`Apply` 改的是调用方传入的状态副本，失败时调用方丢弃副本。

1. 从签名恢复发送方。恢复失败则返回错误。
2. 交易 nonce 必须等于发送方当前 nonce。
3. 金额必须小于等于发送方余额。
4. 收款方余额加上金额不得溢出 `uint64`，否则返回错误，状态不动。
5. 发送方 nonce 加 1，余额减去金额。收款方不存在就建一个 nonce 为 0 的账户，再加上金额。

发送方和收款方是同一地址时，余额不变，nonce 仍加 1。测试直接调用 `Apply`，不休眠。

## 链与出块

链从创世块开始。`Head` 是最新区块。只有 A 调用 `Mine`。

`Mine` 从本机交易池挑交易，在头状态的副本上按顺序 `Apply`，然后生成新块：

- 父哈希等于当前头的哈希
- 交易列表是实际执行成功的那些
- 状态根是执行后的根
- 高度是头高度加 1

挑选规则：按 `Pending` 的顺序看每个发送方。从该账户当前 nonce 起，nonce 必须连续。碰到缺口，或这笔交易 `Apply` 会失败，就停在这个发送方，后面的 nonce 留在池里。选中的交易从池里删除。池为空时仍然出空块，状态根保持不变。

`Append` 只接受同时满足下面三条的块，否则返回错误，链和状态都不变：

- 父哈希等于当前头的哈希
- 用同样的规则重放交易，算出的状态根等于块里的状态根
- 按「字节编码」算出的哈希等于块上的哈希

## 进程与 HTTP

A 和 B 都监听，都接受用户交易，都提供本机状态查询。交易只向 A 汇合，因为只有 A 出块。

`cmd/node`：

- `--listen`。用户没写这个参数时，A 用 `127.0.0.1:8545`，带 `--peer` 的 B 用 `127.0.0.1:8546`。
- `--interval`，默认 `1s`。没有 `--peer` 时，进程是 A，按这个间隔调用 `Mine`。
- `--peer`。非空时进程是 B，值是 A 的 URL，例如 `http://127.0.0.1:8545`。B 不调用 `Mine`。
- `--poll`，默认 `200ms`。B 两次拉块之间的间隔。

两边都提供：

`POST /tx`

```json
{"to":"0x0000000000000000000000000000000000000001","value":1,"nonce":0,"sig":"0x"}
```

A 按交易池规则准入。成功返回 `204`。拒绝返回 `400`，正文是错误文本。

B 先按自己的账本和交易池做同样的准入。本地拒绝时返回 `400`，不转发。本地通过后，把同一个 JSON 正文 `POST` 到 A 的 `/tx`。A 返回 `204` 时，B 保留这笔交易并返回 `204`。A 返回拒绝，或连不上 A 时，B 从自己的池里删掉这笔，把错误返回给用户：A 的 `400` 原样转成 `400`，连不上 A 返回 `502`。

`GET /status` 两边都有，读的是本机链：

```json
{"height":0,"stateRoot":"0x","head":"0x"}
```

只有 A 提供 `GET /blocks?after=<height>`。返回高度大于 `after` 的块，按高度升序。缺省 `after` 等于 0，因此不含创世块。每块包含 `height`、`parentHash`、`stateRoot`、`hash`、`txs`。`txs` 里每笔有 `to`、`value`、`nonce`、`sig`。

用户只把交易发给 A 时，B 的池里可以没有它。B 拉到含这笔交易的块并 `Append` 成功后，状态追平。用户发给 B 时，B 转发到 A，两边池里都有；A 出块后 B 再拉块。发给 B 之前，两边高度应当已经一致，因为 B 用本机状态做准入。

B 拉块：请求 A 的 `GET /blocks?after=<本地高度>`，按顺序 `Append`，并从本机池删掉块里的交易。空列表是正常结果。请求失败、状态码不是 200、JSON 无法解析、或 `Append` 拒绝，都返回错误。

B 的进程循环在这个错误上停止，把错误打印到标准错误，以状态码 1 退出。A 关掉后，下一次拉块失败，B 就这样退出。没有新块时继续轮询，不退出。

`cmd/send`：

- `--url`，A 或 B 的地址
- `--to`，收款地址
- `--value`
- `--nonce`，必填
- `--key`，私钥十六进制，默认演示私钥

它签好名，`POST /tx`，失败时把状态码和正文打到标准错误并以状态码 1 退出。

## 测试

用表驱动测试。测试同步靠直接调用 `Mine`、`Apply`、单次跟随，不使用 `time.Sleep`。

- 三种类型的字段能放进去并读出来。区块哈希由父哈希、交易、状态根决定，改任何一项哈希都变。
- 演示私钥推出的地址等于上面的测试向量。合法签名 `Verify` 通过；改签名下标 10 后失败。
- 交易池三种拒绝，以及按 nonce 排列。
- 一笔转账后发送方 nonce 加 1，双方余额正确。
- 状态根：插入、修改、删除后变化；同一批账户根相同；空根等于上面的常量。
- 链接受父哈希接得上、状态根算得对的块。父哈希不对，或状态根被改过，都拒绝。
- 进程测试：A 用 `httptest` 起来，向 A 提交一笔交易并 `Mine`。B 单次跟随之后，高度和状态根与 A 相同。把 A 关掉再跟随一次，返回错误。
- 再测一条：交易 `POST` 到 B。B 的池和 A 的池都有这笔。A `Mine` 之后 B 单次跟随，两边状态根相同，这笔从两边的池里消失。
