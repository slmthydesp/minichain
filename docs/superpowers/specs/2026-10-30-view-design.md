# 链查看页

日期：2026-10-30

一个单独的查看进程提供一页。页面上填出块进程的 `主机:端口`，可以同时看多个。每列画该进程的规范链：最新的块在上面，往下接到更老的块。数据只用现有的 `GET /status` 和 `GET /blocks`。出块进程不改。

浏览器只请求查看进程。查看进程再去请求出块进程，因此出块进程不加 CORS。

## 不做

新的依赖、节点改动、CORS、侧链、账户列表、交易池、交易签名的展示、自动化浏览器测试。测试不调用 `time.Sleep`。

## 进程

`cmd/view` 只有 `--listen`。没写时监听 `127.0.0.1:8080`。监听失败把错误打到标准错误，以状态码 1 退出。

处理逻辑放在 `view`。`view.Handler()` 返回 `http.Handler`。页面文件是 `view/static/index.html`，用 `go:embed` 打进二进制。`go:embed` 不能引用包目录外面的文件，所以页面不放在仓库根下。

`view` 不导入 `chain`。它不解析区块，只转发 HTTP。除了 `GET /`、`GET /api/status`、`GET /api/blocks`，其他路径返回 `404`。

## 代理

`GET /` 返回该页面，`Content-Type` 为 `text/html; charset=utf-8`。

`GET /api/status?node=<主机:端口>` 请求 `http://<主机:端口>/status`。

`GET /api/blocks?node=<主机:端口>&after=<高度>` 请求 `http://<主机:端口>/blocks?after=<高度>`。先检查 `node`，再检查 `after`。`after` 这个查询键缺省时，上游 URL 不带查询。键存在但不是十进制 `uint64`（含空字符串）时，不访问上游，返回 `400`，正文 `bad after`。合法的 `after` 转发时不保留前导零，因此 `076` 变成 `after=76`。`after=0` 原样转发为 `after=0`，不当成缺省。

`node` 先去掉两端空白，再用 `net.SplitHostPort` 拆开。端口必须在 1 到 65535。主机非空，且不含 `@`、`/`、`\` 或空白。不接受协议、路径、账号。非法时返回 `400`，正文 `bad node`，且不访问上游。非法例子：空、`127.0.0.1`、`http://127.0.0.1:8545`、`127.0.0.1:8545/status`、`127.0.0.1:0`。两端有空白但去掉后能拆开的，合法。合法例子：`127.0.0.1:8545`、`localhost:8545`、`[::1]:8545`。上游 URL 使用同一套规范写法，IPv6 主机加方括号，例如 `http://[::1]:8545/status`。

上游的状态码和正文原样返回，并带上上游的 `Content-Type`（上游没设就不设）。客户端超时 3 秒，不跟随重定向：上游的 3xx 把状态码和正文转回。连接失败、超时、或读正文失败，返回 `502`，正文 `unreachable`。

## 页面

输入框占位符是 `127.0.0.1:8545`，按钮文字是「添加」。用和代理相同的规则检查地址。不合法时不添加，输入框旁显示「地址要写成主机:端口」。

合法地址规范成 `主机:端口`（IPv6 写成 `[主机]:端口`，端口不保留前导零）。名单存在 `localStorage` 键 `minichain.view.nodes`，值是 JSON 字符串数组。刷新后还在。读出来不是字符串数组时，当成空名单。同一个规范地址再添加一次，不出现第二列。

每列从左到右排，放不下就横向滚动。列头是规范地址和按钮「移除」。移除从名单和页面删掉这一列。

摘要三行：高度、链头、状态根。链头和状态根去掉一个前导 `0x` 或 `0X` 后，若十六进制正文不少于 12 位，显示前 8 位、省略号、后 4 位；不足 12 位则显示全文。悬停提示是 JSON 里的原文字。

块按 `height` 从大到小排，不依赖数组原来的顺序。块与块之间一条竖线。每块显示高度、交易笔数、哈希缩写（规则与链头相同）。点一块展开：父哈希、状态根、coinbase 用全文，每笔交易显示收款地址、金额、nonce，不显示签名。再点这块收起。点另一块时，原先展开的收起。同一列同时只展开一块。刷新后，新窗口里仍有同一 `hash` 就保持展开，否则收起。

窗口是最近 24 块。一轮是先请求 `/api/status`，再请求 `/api/blocks`。高度小于等于 24 时，`after` 为 0；否则 `after` 为高度减 24。`/blocks` 不含创世块，页面也不画创世块。高度大于 24 时，列底写「更早的块未显示」。高度为 0 时链是空的，不显示这句，也不是错误。

两次请求都是 200 且 JSON 能按下面的形状解析时，才换上这一列的摘要和块。否则保留上一次成功的内容。还没有成功过时，只显示错误，不画块。

- 状态是对象，字段 `height`、`stateRoot`、`head`。`height` 是 JSON 数字，并且是 0 到 2^53−1 的整数（含）。更大的数在浏览器里不能精确表示，这轮算解析失败。`stateRoot` 和 `head` 是字符串。
- 块列表是数组。每块有 `height`、`parentHash`、`stateRoot`、`hash`、`coinbase`、`txs`。`height` 的整数范围与状态相同。三个哈希字段和 `coinbase` 是字符串。每笔交易有 `to`（字符串）、`value` 和 `nonce`（与 `height` 相同的整数）。多出来的字段忽略。`txs` 不是数组，或任一必填字段类型不对，则这轮算解析失败。

添加之后立刻拉一次。之后每秒一轮。某一列上一轮还没结束，就跳过这一列，其他列照常。

还没有地址时，页面写「添加一个出块进程的地址」。

某一列失败不影响其他列。错误写在列头下面。上一次成功画出来的摘要和块留着：

- 查看进程返回 `502`：这一列显示「连不上」。
- 其他非 200：这一列显示该状态码。
- 200 但 JSON 不是上面的形状：这一列显示「回应无法解析」。

## 测试

`view` 用 `httptest`，表驱动，不休眠。

- `node` 为上面列出的非法值时，`/api/status` 和 `/api/blocks` 都返回 `400`，正文 `bad node`，且没有访问上游。
- `after` 为 `12abc` 时返回 `400`，正文 `bad after`，且没有访问上游。
- 上游返回的状态码、`Content-Type` 和正文，由 `/api/status` 原样转回。
- `/api/blocks?after=76` 时，上游收到的路径是 `/blocks?after=76`。缺省 `after` 时，上游路径是 `/blocks`。
- 上游关掉时返回 `502`，正文 `unreachable`。
- 上游返回 `302` 时，查看进程也返回 `302` 和上游正文，且不请求 `Location`。
- `GET /` 返回 `200`，`Content-Type` 以 `text/html` 开头，正文含「添加一个出块进程的地址」。
