# 分叉与回滚

日期：2026-10-30

在现有转账链上，每个进程都能出块。两个进程可以在同一个父块上各出一块。节点保存这些分叉，用同一条规则选出链头；换链头时退回被放弃的交易，状态切到新链头的快照。仍然不落盘。

Gas、回执、交易替换、合约、默克尔树、EIP-155 不在这次里。

## 不做

新的依赖、数据库、EVM、gas、Merkle Patricia Trie、EIP-155、节点发现、权益证明。测试不调用 `time.Sleep`。

## 区块

`Block` 增加 `Coinbase Address`。创世块的 coinbase 是 20 个 0。

区块哈希原文改为：

```text
parentHash   32
stateRoot    32
coinbase     20
txCount      uint32
txs          每笔交易的 101 字节规范形式
```

高度不进入哈希。coinbase 不同，空块的哈希也不同。两个进程用同一个 coinbase、同一父块、同一批交易时，块哈希相同，这是同一块。

JSON 块多一个字段 `coinbase`，小写十六进制，可以带 `0x`。`decodeBlock` 仍用重算的哈希核对 JSON 里的 `hash`。

## 链的存储

`Chain` 按区块哈希保存块，并为每个块保存执行后的状态副本。链头是其中一个哈希。

`Mine(coinbase Address)` 只延长当前链头。挑选交易的规则不变。选中的交易先留在池里，等这块成为链头后再从池里删掉。池空时仍然出空块。

以太坊的出块也按时间走，不看交易池里有没有交易。合并之后每个时隙 12 秒，轮到的提议者都要发布一块。池是空的，这块里可以没有用户交易，块头和状态根仍然要有。这个时隙没有块，是提议者没有按时发出，不是因为没有交易可打包。合并之前也一样：矿工在没有交易时继续挖，空块可以只带出块奖励。

`Append` 接受任何父块已经在本地的块：

- 哈希已经存在：返回 nil，不改链头、状态和交易池。
- 父块不存在：返回错误 `unknown parent`，什么都不保存。
- 高度不是父块高度加 1：返回错误 `bad height`，什么都不保存。
- 在父块状态的副本上按顺序 `Apply`，根与块里的状态根不一致，或某一笔 `Apply` 失败：返回错误，什么都不保存。
- 通过后保存块和状态副本，再做链头选择。

`Has(hash)` 报告这块是否已保存。`BlocksAfter(height)` 只返回当前规范链上高度大于 `height` 的块，按高度升序。侧链上的块不出现在这个列表里。

`Head` 返回规范链头。`Account` 读规范链头的状态。

## 链头选择

在已保存的全部块里选规范链头：

1. 高度更大的优先。
2. 高度相同，哈希字节更小的优先。

所以同一高度的两块，所有节点在都看到这两块之后会选出同一个链头。更长的链会换掉较短的链，不管较短那条的哈希是不是更小。

## 换链头

新链头和旧链头不同才处理交易池。找到两条链的最近公共祖先。

- 新链头这段里的交易（祖先之后，含新链头）按发送方和 nonce 从池里删除。
- 旧链头这段里的交易，如果同一个发送方和 nonce 已经出现在新链头那段，就不再放回。其余的按新链头的余额和 nonce 重新 `Add`。`Add` 失败就留在池外。

状态直接换成新链头已保存的副本，不从创世重放。

因此：

- 被放弃的块里的转账回到池里，收款方余额回到新链头上的值。
- 新链已经花掉的 nonce 不会把旧分支上的同一 nonce 放回池里。
- 只是接到当前链头后面的块，不会把别的交易放回池里。

## 进程

每个进程都出块，也都提供块。

`cmd/node`：

- `--listen`。没写时，没有对等方用 `127.0.0.1:8545`，写了对等方用 `127.0.0.1:8546`。
- `--interval`，默认 `1s`。每个进程都按这个间隔调用 `Mine`。
- `--coinbase`，出块写入的地址。默认是演示账户 `0xf39fd6e51aad88f6f4ce6ab8827279cfffb92266`。两个进程要看到分叉，就各自写一个不同的地址。
- `--peers`，逗号分隔的 URL。空表示没有对等方。
- `--poll`，默认 `200ms`。有对等方时，两次同步之间的间隔。

`--peer` 去掉，只保留 `--peers`。

有对等方时，同步失败把错误打印到标准错误，进程继续出块和监听。没有新块时继续轮询。出块失败或监听失败仍以状态码 1 退出。

## HTTP

两边都提供原来的 `POST /tx`、`GET /status`、`GET /blocks?after=<height>`。

新增 `GET /block?hash=<hex>`。找到返回这一块的 JSON，对象字段与 `/blocks` 里的元素相同。哈希不合法返回 `400`。本地没有这块返回 `404`。

`POST /tx`：本地准入失败返回 `400`，不转发。本地成功之后，把同一个 JSON 转发给每个对等方。转发失败、对等方拒绝、或读回应失败，都不从本地池删除，并仍向用户返回 `204`。用户看到的是本机是否收下这笔交易。

## 同步

`FollowOnce` 对每个对等方做一次：

1. `GET /status`，读出链头哈希。
2. 本地已有这个哈希就结束这个对等方。
3. 否则 `GET /block?hash=` 取这块，再取它的父块，直到父块本地已经有。
4. 从最老的那块开始按顺序 `Append`。

对等方连不上、状态码不是预期、JSON 无法解析、或 `Append` 拒绝，这次 `FollowOnce` 返回错误。空的追赶（链头已有）返回 nil。

## 测试

链：

- 只改 coinbase，区块哈希变化。
- 两条高度相同的链，链头是哈希较小的那块；另一块仍 `Has`。
- 另一条链多一块之后，链头改到更长的那条。被放弃的转账回到池里，收款方余额回到更长那条链上的值。更长那条是空块时，余额是创世余额。
- 同一块 `Append` 第二次返回 nil，高度和池都不变。
- 父块未知时拒绝，链头仍是创世。

节点：

- 跟随者先收下进程 A 的块，再向已经多出两块的进程 B 同步。跟随者要沿着父哈希把 B 的祖先块取回来，链头和状态根与 B 相同。
- 交易发给一个对等方连不上的节点时，返回 `204`，交易留在本机池里。
